# 单设备极致优化方案：迁移 LibWrt 25.12-nss + 分支试编译

## 目标
仅针对 JDCloud RE-SS-01（魔改亚瑟，IPQ6010）一款设备，把 NSS 性能榨到极致。源码从 `LiBwrt/openwrt-6.x` (main-nss) 迁移到 `LiBwrt/LibWrt` (25.12-nss)。GitHub Actions 自编译，**改动先推 `dev` 分支试编译，编译成功+产物校验通过后自动 fast-forward 合并到 `main` 并发 Release**，失败则留在 dev 不动 main。

## Step 3：libwrt.sh 瘦身去重（关键）

### 删除冗余段（LibWrt 25.12-nss 已内置）
- **第 12 节 cpuusage 的 rpcd hook sed**：LibWrt `992_set-nss-load.sh` 已做同样的事（popens /sbin/cpuusage），删 libwrt.sh 对应 sed，保留 `/sbin/cpuusage` 脚本本身（LibWrt 可能没写这个二进制，需保留我们写的）
- **第 17 节 `scaling_governor 'schedutil'` sed**：LibWrt `config-6.12` 已 `CONFIG_CPU_FREQ_DEFAULT_GOV_SCHEDUTIL=y`，删 sed；保留 `auto_scale 'off'`（LibWrt 没做）

### 删除冲突段（LibWrt 自带值不优，必须 override）
- **在 libwrt.sh 顶部加**：`rm -f target/linux/qualcommax/base-files/etc/uci-defaults/993_set-ecm-conntrack.sh`（它把 `nf_conntrack_max` 改回 65535，与我们的 163840 冲突）
- 保留我们第 6 节 sysctl.conf 末尾的 `nf_conntrack_max=163840`

### 保留段（LibWrt 没做或我们更优）
- 第 1 节删冲突包：保留
- 第 2~3 节克隆 argon/lucky/mosdns + Makefile 修复：保留
- **第 4b 节 BBR/FQ patch**：保留（LibWrt config-6.12 没开 BBR/FQ，仍在 generic/config-6.12 被禁用）
- 第 5~6 节 sysctl：保留
- 第 7 节 rc.local 兜底：保留
- 第 8 节 nss-status：保留
- 第 9 节 Passwall 超时：保留
- 第 10 节 sysupgrade 备份：保留
- 第 11 节 cron + WG watchdog：保留
- **第 12 节 cpuusage 二进制**：保留脚本本体，删 rpcd hook sed
- 第 13 节 tempinfo：保留
- 第 14 节 Argon 配色：保留
- **第 15 节 SMP affinity**：保留我们的 init.d 脚本（比 LibWrt 自带的更细——我们明确分了 reo2host 4 核/wbm2host/ppdu/edma/nss_queue0/bam_dma），但需先 diff LibWrt 的 `base-files/etc/init.d/smp_affinity`，如有更好值则吸收
- **第 16 节 NSS START=88**：保留
- 第 17 节 pbuf auto_scale off：保留（删 schedutil 那行）

## Step 4：增量极致优化（在 libwrt.sh 末尾追加新段）

### 第 18 节 conntrack hashsize 调优
不只是 max，还要调 hashsize（默认 max/4）：
```sh
cat >> files/etc/sysctl.conf <<EOF
# conntrack hash 表大小优化（=max/2，降低哈希冲突）
net.netfilter.nf_conntrack_buckets=81920
EOF
```
（163840/2=81920，更低的冲突率）

### 第 19 节 网络软中断负载均衡
```sh
cat >> files/etc/sysctl.d/99-optimize.conf <<EOF
# RPS/RFS 软中断多核分发
net.core.rps_flow_limit=16384
net.core.netdev_max_backlog=2500
net.core.netdev_budget=600
net.core.netdev_budget_usecs=8000
# optmem 预分配
net.core.optmem_max=262144
EOF
```

### 第 20 节 TCP 低延迟 + 缓冲深化
```sh
cat >> files/etc/sysctl.conf <<EOF
# TCP 低延迟 + 缓冲
net.ipv4.tcp_low_latency=1
net.ipv4.tcp_window_scaling=1
net.ipv4.tcp_tw_reuse=1
net.ipv4.tcp_fin_timeout=15
net.ipv4.tcp_keepalive_time=300
net.ipv4.tcp_syncookies=1
net.ipv4.tcp_max_syn_backlog=8192
net.ipv4.tcp_max_tw_buckets=20000
EOF
```

### 第 21 节 文件系统 + 内存回收（NAS 场景）
```sh
cat >> files/etc/sysctl.d/99-optimize.conf <<EOF
# 脏页回写（Samba/NAS 更稳）
vm.dirty_ratio=10
vm.dirty_background_ratio=5
vm.dirty_expire_centisecs=1200
vm.dirty_writeback_centisecs=1200
# 内存过量提交策略
vm.overcommit_memory=1
vm.min_free_kbytes=32768
EOF
```

### 第 22 节 NSS 收发队列绑核（强化版）
在 50_nss_tweaks.sh / libwrt.sh 第 15 节基础上，给 `nss_queue0~3` 全部绑核（LibWrt 默认只绑 queue0）：
```sh
set_affinity 'nss_queue0' 2-3 1
set_affinity 'nss_queue1' 2-3 1
set_affinity 'nss_queue2' 3 1
set_affinity 'nss_queue3' 3 1
```
（需先确认 IPQ6010 NSS 实际有几个 queue，从 `/proc/interrupts` 抓真实 IRQ 名）

## Step 5：新 workflow `.github/workflows/build.yml`

### 触发与分支策略
```yaml
on:
  workflow_dispatch:
  push:
    branches: [ dev ]   # 只监听 dev 分支 push
    paths: [ 'configs/**', 'libwrt.sh', 'scripts/**', '.github/workflows/build.yml' ]
```

### 编译成功 → 自动合并 main + Release
workflow 末尾加：
```yaml
- name: Merge dev to main (编译成功才跑)
  if: steps.compile.outputs.status == 'success'
  run: |
    git config user.name "github-actions[bot]"
    git config user.email "actions@github.com"
    git fetch --unshallow || true
    git checkout main
    git merge dev --ff-only
    git push origin main

- name: Release (合并 main 后发版)
  if: steps.compile.outputs.status == 'success'
  uses: ncipollo/release-action@v1
  with:
    tag: R${{ env.DATE }}
    name: R${{ env.DATE }} for JDCloud RE-SS-01
    allowUpdates: true
    artifacts: ${{ env.FIRMWARE_PATH }}/*
    body: |
      内核: ${{ env.VERSION_KERNEL }}
      源码: LiBwrt/LibWrt@25.12-nss
      ${{ env.VERSION_INFO }}
      ...
```

### 缓存强化
```yaml
- name: Cache Toolchain + ccache
  uses: HiGarfield/cachewrtbuild@main
  with:
    ccache: true                    # 旧版 false，改 true
    mixkey: libwrt-25.12-nss-jdcloud-re-ss-01
    prefix: ${{ env.OPENWRT_PATH }}
```

### 编译步骤（沿用原 yml 的内联流程，仅改 env + 加 ccache）
- 环境初始化 → maximize-build-space → checkout dev → clone LibWrt 25.12-nss → 解析变量 → 缓存 → feeds update → 跑 libwrt.sh → make defconfig → 强制 BBR/FQ → make download → make -j$(nproc) || make -j1 V=s → 整理产物 → 合并 main + release

### main 分支保护
- Settings → Branches → Branch protection rules → main：Require pull request / Require status checks（build 必须通过）
- dev 分支可直接 push

2. **抓 LibWrt 的 `target/linux/qualcommax/base-files/etc/init.d/set-irq-affinity`**（如果有），确认与我们的不重复

4. **确认 LibWrt 是否已内置 `cpuusage` 二进制**：如果有，删 libwrt.sh 第 12 节本体；没有则保留

## 风险与回滚
- **风险1**：LibWrt 25.12-nss 分支结构变化 → 已确认内核 6.12、分支名正确
- **风险2**：libwrt.sh 与 LibWrt 内置脚本冲突 → Step 3 删冗余/删冲突 + Step 6 diff 验证
- **风险3**：补丁失效 → workflow 加 `git am --check` 预检
- **风险4**：dev 编译失败 → main 不受影响（只合并成功 run）
- **回滚**：所有旧文件在 `legacy/*.orig`，git 分支独立，main 永远有上次成功的固件可下载
