## 二、bypass 打开后的机制变化

### 2.1 内核层发生了什么

nikki 生成的 nft 表 `inet nikki` 里，每条链都有这两行（位置在 `@reserved_ip` 之后、`jump router_redirect` 之前）：

```nft
ip  daddr @china_ip  counter ... return
ip6 daddr @china_ip6 counter ... return
```

含义：**目标 IP 属于中国 IP 段 → 直接 `return`，不 redirect / 不 tproxy → 流量根本不进 mihomo。**

所以 bypass 打开后，规则表里凡是「目标是 CN IP 但写了代理」的条目**实际上已经失效**，只是没人告诉你。

### 2.2 实测：哪些规则真的失效了

逐个域名解析真实 IP，再 `nft get element inet nikki china_ip '{ <ip> }'` 判定：

| 类别 | 结果 |
|---|---|
| 需要代理的域名（YouTube/Google/GitHub/AI/流媒体/Telegram/Oracle/zdgw…） | **只有 1 个**落到 CN IP：`services.googleapis.cn` → `211.95.34.139` |
| 国内域名（40 个抽样：jd/163/weibo/zhihu/bilibili/iqiyi/12306/gov.cn/icbc…） | 39 个 real-IP + CN → 内核直通 ✅；1 个（`www.ruanyifeng.com`）走 Cloudflare 是 fake-IP，正确 |
| 「国内 CDN」（bootcdn / staticfile / bootcss） | 真实 IP 在 **HK / SG / NL**，不在 `@china_ip` → bypass 抓不到是**正确**的 |

### 2.3 性能反证：那些"国内 CDN"不该改直连

实测 direct vs proxy：

| 域名 | direct | proxy | 结论 |
|---|---|---|---|
| `www.bootcss.com` | **1.571s** | **0.381s** | 代理快 4 倍 |
| `cdn.bootcdn.net` | 0.380s | 0.381s | 持平 |
| `cdn.staticfile.org` | 0.326s | 0.389s | 持平 |
| `cdn.jsdelivr.net`（对照组） | 0.315s | 0.342s | 持平 |

`whois` 确认：`103.198.200.204` = HK Kaopu Cloud、`45.125.35.167` = HK CDN1、`202.181.25.20` = HK Cloudie、`43.174.102.51` = SG ACE、`43.152.43.121` = NL Amsterdam。
**它们名字像国内站，实际是海外 CDN** → 保持走代理。

> 我最初按名字直觉加了 4 条「国内 CDN 改直连」，实测后**全部回滚**，只保留 1 条有证据的。

## 三、真正的隐藏故障：sniffer 一直是关的

### 3.1 怎么发现的

排查「`oc-cn-domain` 里的域名，如果真实 IP 是非 CN，会怎样」时发现：

- `oc-cn-domain` 成员拿到 **real-IP**（不走 fake-IP）
- 但 `@china_ip` 里没有这些 IP（如 `www.workbuddy.ai` → `43.160.158.125`）
- 于是它们**会进 mihomo**
- 而 mihomo 只有 IP、没有域名 → 所有 `DOMAIN/GEOSITE/RULE-SET` 规则（共 **39 条**）全部无法匹配 → 漏到 `MATCH,🐟 漏网之鱼`

**唯一的救法就是 sniffer**：从 TLS SNI / HTTP Host 把域名捞回来。

### 3.2 实测 sniffer 确实是关的

```sh
$ curl -s -H 'Authorization: Bearer 917999' http://127.0.0.1:9090/configs | jq .sniffing
false
```

`run/config.yaml` 里**根本没有 `sniffer:` 段**。

### 3.3 踩坑：两个开关，只开一个没用

`/etc/nikki/ucode/mixin.uc:129-150` 的逻辑：

```js
config['sniffer']['enable']              = uci_bool(uci.get('nikki','mixin','sniffer'));              // ← 总开关
config['sniffer']['force-dns-mapping']   = uci_bool(uci.get('nikki','mixin','sniffer_sniff_dns_mapping'));
config['sniffer']['parse-pure-ip']       = uci_bool(uci.get('nikki','mixin','sniffer_sniff_pure_ip'));
if (uci_bool(uci.get('nikki','mixin','sniffer_sniff'))) { config['sniffer']['sniff'] = {...} }        // ← 子块
```

- `sniffer`（**总开关**，控制 `enable:`）—— 之前**未设置** = 0
- `sniffer_sniff`（子块，控制 `sniff:` 里 HTTP/TLS/QUIC 端口）—— 之前是 1

**只设 `sniffer_sniff=1` 只会生成 `sniff:` 子块，`enable:` 仍然是 false**，API 依旧 `sniffing:false`。
（我第一次就是只设了 `sniffer_sniff`，重启后 `sniffing` 仍为 false，白折腾一轮。）

**另一个坑**：往 `/etc/nikki/mixin.yaml` 手写 `sniffer:` 段是**无效**的 ——
`init.d/nikki:186` 用 `ucode -S mixin.uc | yq eval-all '. * $item'` 把 ucode 生成的内容**乘**到 run config 上，ucode 输出的 `sniffer.enable=false` 会覆盖手写值。必须走 uci。

### 3.4 最终修复

```sh
uci set nikki.mixin.sniffer='1'                    # 总开关
uci set nikki.mixin.sniffer_sniff='1'              # 子块（HTTP/TLS/QUIC 端口）
uci set nikki.mixin.sniffer_sniff_dns_mapping='1'  # force-dns-mapping
uci set nikki.mixin.sniffer_sniff_pure_ip='1'      # parse-pure-ip（纯 IP 建连也嗅探）
uci commit nikki && /etc/init.d/nikki restart
```

验证：

```sh
$ curl -s -H 'Authorization: Bearer 917999' http://127.0.0.1:9090/configs | jq .sniffing
true

# run/config.yaml
sniffer:
  enable: true
  force-dns-mapping: true
  parse-pure-ip: true
  sniff:
    HTTP:  { port: ["80","8080"],   override-destination: true }
    TLS:   { port: ["443","8443"],  override-destination: true }
    QUIC:  { port: ["443","8443"],  override-destination: true }
```

**运行时证据**：连接列表里出现 `sniffHost=amr-link.open-design.ai`（原本 host 为空的连接，域名被 SNI 恢复）。

| `services.googleapis.cn` | **改直连** | 唯一一个「zdgw 想走代理但真实 IP 是 CN」的域名，内核已强制直连 |
| `bootcdn.net` / `staticfile.org` / `bootcss.com` | **不改** | 真实 IP 在 HK/SG/NL，bypass 抓不到；实测代理反而更快 |
| `www.workbuddy.ai` / `www.landiannews.com` / `www.longzhu.com` | **不改规则** | 它们在 `oc-cn-domain` 里但 IP 非 CN；**sniffer 开启后域名能恢复**，`oc-cn-domain` 规则正常命中 |

## 八、经验沉淀（下次别再踩）

1. **bypass 与规则表是两套机制，会互相遮蔽。** bypass 在内核 nft 层 `return`，优先级**高于** mihomo 规则。开 bypass 后必须重新核对「有没有规则想代理 CN IP」。
2. **nikki 的 sniffer 是两个 uci 开关**：`mixin.sniffer`（总开关→`enable:`）+ `mixin.sniffer_sniff`（子块→`sniff:`）。只设后者不生效。判断标准只看 `GET /configs` 的 `.sniffing`。
3. **不要手改 `/etc/nikki/mixin.yaml`** —— ucode 会覆盖。所有 mixin 项都必须走 `uci set nikki.mixin.*`。
4. **别按域名猜归属。** bootcdn/staticfile/bootcss 名字很"国内"，实际 IP 在 HK/SG/NL。判定必须 `nft get element inet nikki china_ip '{ <ip> }'`。
5. **`sniffer_sniff_pure_ip=1` 很关键**：纯 IP 建连（无 DNS）也能靠 SNI 恢复域名，这是 bypass 下 real-IP 域名不失效的保障。
6. **验证脚本别超时**：SSH 执行长脚本（>120s 采样）会 `PipeTimeout`。改用 `( ... ) &` 后台跑 + 轮询标记文件。
7. **router 的 `sleep` 不支持小数**（`sleep 2.5` 报 `invalid number`），只能整数。
