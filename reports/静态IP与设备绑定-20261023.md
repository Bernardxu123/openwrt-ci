# 局域网静态 IP 绑定与优化建议（2026-10-23）

> 实测时间：2026-10-23 18:52–19:02（路由器 ponwrt QWRT R26.10.21 / `192.168.31.1`）
> 工具：`tools/pin_leases_20261023.py`；路由器备份 `/etc/config/dhcp.bak-20261023`、`/etc/hosts.bak-20261023`

## 一、结论：要不要固定静态 IP？

**要固定，但不是"全部固定"。** 判断标准三条：

| 类别 | 为什么要固定 | 处理 |
|---|---|---|
| 基础设施（路由器/AP/主力 PC） | 管理入口，IP 变了就找不到 | 必须 |
| 会被按 IP 访问、或被防火墙/代理规则引用的设备（电视/摄像头/媒体） | 规则与访问依赖固定地址 | 建议 |
| **自己配了静态 IP 且落在 DHCP 池 100–249 内**的设备 | 可能被动态分配撞车（实测 5 台） | 必须加保留 |
| 普通手机/平板（随机 MAC） | 随机 MAC 会轮换，钉了也会静默失效（平板已实证漂移） | 尽力/需先关随机 MAC |
| 访客、无名随机 MAC 设备 | 无访问需求 | 不绑 |

**本次实施原则：全部按设备"当前 IP"原样钉死，不改任何设备 IP、不改 DHCP 池、不动无线与代理配置。**

## 三、改了什么

1. DHCP 静态租约 **7 → 23 条**（`uci show dhcp | grep -c '=host'` = 23）。
2. **修正命名错位**：原 `pc_wifi`（80:fa:5b→.218）其实是**有线网卡**、`pc_eth`（68:3e:26→.222）其实是 **WiFi**，已删除 `pc_wifi`，改名 `pc_wlan`（.222）/`pc_eth`（.218）。
3. `/etc/hosts` 增补静态设备名（DHCP 拿不到名字的设备）：
   - `192.168.31.138  ap ap.lan xiaomi_ap xiaomi_ap.lan`
   - `192.168.31.218  pc_eth pc_eth.lan`
   - `192.168.31.170/219/145/146/179  dev170/dev219/dev145/dev146/dev179(.lan)`
4. 未改：DHCP 池（.100–.249 / 12h）、无线、OpenClash、防火墙、任何设备自身配置。

## 五、风险与注意事项

1. **随机 MAC 是最大隐患**：P30 Pro、SGT-AL10、小米 14 Pro(.214)、平板(.122) 都是本地管理位（随机）MAC。
   实测平板 MAC 已从 09-30 记录的 `52:b9:ab:5f:63:09` 漂到 `e6:33:6a:a9:24:e3`，说明租约可能在某次换网络后静默失效。
   **根治**：在手机 WiFi 设置里对 `bernard` / `bernard_5G` 选"使用设备 MAC"，再用真实 MAC 重新绑定。
2. **小米 14 Pro 疑似两台/一台双记录**：`.221`（真实 MAC，HOSTNAME `mi14pro`，当前离线）+ `.214`（随机 MAC，HOSTNAME `Xiaomi-14-Pro`，在线）。
   若确认是同一台，关随机 MAC 后统一用 `88:6c:60:1f:ee:60` 钉 `.221`，删 `.214`。
3. **PC 双网卡**：有线网卡处于 Disabled，只有 WiFi 在用。若以后同时启用有线+WiFi，会在同一网段出现两个源 IP（.218/.222），做"按设备规则"时两个都要覆盖。
4. 保留条目不会立刻改变已在线设备（IP 本来就相同），只在下次续约/重连时生效。

## 六、其他优化建议（本次未实施）

### P0（已随本次完成）

- 文档纠偏：`AGENTS.md` 设备 IP/MAC 已按实测更新（原记录 PC=.106、mi14=.127、TV=.115、AP=.158 全部作废）。
- 静态设备名字解析（`ap.lan` 等原本 NXDOMAIN，因为自配静态设备没有 DHCP 租约）。

### P1（建议，需拍板）

1. **手机关随机 MAC**（见 §五1），否则 B 组里 4 台手机的租约只是"尽力"。
2. **内存余量偏紧**：`MemAvailable` ≈ 90–98MB，mihomo RSS 121MB，410MB 总量、零 swap；10-22 09:45 曾因**双实例**被 OOM 杀过一次。建议保持单实例 watchdog；如需保险可给 mihomo 设 `GOMEMLIMIT≈200MiB`（会略增 GC CPU，需实测）。
3. **2.4G 弱终端**：小米 14 Pro 在 2.4G 仅 -78dBm、微波炉 -77dBm；本固件无 802.11k/v 引导。可考虑 2.4G 只留给 IoT、手机只连 5G，或调低 2.4G 功率——属无线改动，建议单独做并回归。

### P2（记录，暂不做）

4. IPv6 PD 噪声：3 条 /60 前缀（含 3 台米家设备自行请求 PD），动它影响全局 v6，收益低。
5. `crontab` 为空：目前无自动任务（避免订阅 reload 断流），保持现状。
6. DHCP 池与静态 IP 混用：dnsmasq 会自动排除，不必重排网段。
7. OpenClash `en_mode` 实为 `fake-ip-mix`（文档原写 `fake-ip`），已在 AGENTS.md 更正。
