## 0. 一句话结论

本次审查覆盖 **三层配置（UCI 启动配置 → `/etc/nikki/mixin.yaml` → profile）** 与 **两层内核旁路（`inet nikki` nft + mihomo 规则）**，结论：

1. **找到一个真 bug**：`sniffer` 的端口键被 nikki 写成 `port`，mihomo 只认 `ports` ⇒ 自定义端口（8080/8443）**从未生效**，静默回落到 80/443。
2. **拆掉两颗地雷**：UCI 里的 DNS 上游/策略与 fake-ip 过滤开关都是"看着配了、实际不生效"，一旦在 LuCI 打开会立刻踩 AGENTS §7-4 / Play 下载的坑；已删除其中最危险的 `geolocation-!cn → 1.1.1.1/8.8.8.8` 一条。
3. **证明两处重复并删除**：`DOMAIN,xx.290490.xyz` / `DOMAIN,dsh.290490.xyz` 被 `DOMAIN-SUFFIX,290490.xyz` 同目标完全覆盖（规则 76→74，行为逐条验证不变）。
4. **顺手修掉一个反复抖动的根因**：`dsh.290490.xyz` 的 AAAA 之前走 dnsmasq → 联通 ISP DNS，而该域是 DDNS 记录、ISP 多个缓存实例互相打架（同一时刻阿里已是新前缀、ISP 仍回旧值）⇒ `dsh-dns-guard` 每 15 分钟比对失败 → reload 无效 → **重启 nikki（约 15s 全代理中断）**。改为固定用 `223.5.5.5/119.29.29.29` 解析该域，并在 guard 里加 `POST /cache/dns/flush` 作为第一档修复。

**链路策略本身没动**（`🔐 Google`、`📚 Learn`、`⚡ OpenCode`、`🎬 流媒体` 等选路保持原状）；升级后软件卸载已把下行修到 948–968 Mbps，本轮收益定位在"正确性 / 少中断 / 可维护"，不再许诺提速。

### 内核/规则层的"两层保险"（保留，不算冲突）

- `@china_ip`（7362 段，静态 nft 集合）→ 命中即回内核，**根本不进 mihomo**；规则表里的 `RULE-SET,oc-cn-domain` / `GEOIP,CN` 是长尾兜底。
- **NTP 三层**：fw4 `Redirect-NTP`（DNAT 到路由器）→ nikki `lan_tproxy` 把 UDP 送进 mihomo → 规则 `IP-CIDR 192.168.0.0/16 → 直连` 把它送回路由器 ntpd。core.log 与实测均确认这条链路在跑，每包多一跳但量极小 ⇒ 保留（删任一层都会改变"LAN NTP 强制归路由器"的行为）。
- **QUIC 规则里的 `(NOT,((GEOIP,CN,no-resolve)))` 不是恒真废条**：对 fake-IP 连接恒真，但对"内核 `@china_ip` 没覆盖到的国内纯 IP QUIC"仍有效 ⇒ **不能删**。

## 8. 后续注意（★）

1. **不要用 LuCI「混入配置」整页保存**：`luci-app-nikki` 整页保存会删掉显示"不修改"的手工 uci 项（AGENTS §4.7 前科），可能把 `mixin_file_content` 复位成 0（则 `sniffer.ports` 再次失效）。只走 SSH 或单字段修改。
2. **不要在 LuCI 打开「fake-ip 过滤」或「DNS 上游/策略」开关**：会整体替换 profile 的白名单/上游（见 A1/A2）。
3. **重刷/升级会换 rootfs 文件**（`fw4.uc`、`/usr/sbin/nginx`、`luci app.js`），但 `/etc/nikki/*` 与 `/usr/bin/dsh-dns-guard.sh` 在 keep 内、已验证跨升级保留。
4. **新固件自带 cron `0 4 * * * /etc/coremark.sh`**：跑基线/测吞吐请避开 04:00。
5. `sniffer.port` 旧键仍由 `mixin.uc` 生成、被 mihomo 忽略；等上游修 `ucode/mixin.uc` 后可从 `mixin.yaml` 移除 `ports`（或两者共存亦无害）。
