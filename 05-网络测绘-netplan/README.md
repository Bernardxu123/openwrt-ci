# 户型网络规划器

一个**单文件、离线可用**的家用 Wi‑Fi 覆盖与拓扑规划工具。基于你的户型扫描图自动提取墙体，
用多墙传播模型推算覆盖热力图、逐房间信号、终端速率与信道干扰，并给出补点位置建议。

> 打开方式：直接双击 `index.html`（无需服务器、无需联网、无外部依赖）。

---

## 1. 它是怎么算的

### 1.1 墙体来源（不是手画的）

`build/build.py` 对原始扫描件做了四步处理，产出两个资产内嵌进 `index.html`：

| 步骤 | 做法 |
|---|---|
| 纠偏 | Hough 统计主方向 ≈ **+1.22°**，`warpAffine` 转正 |
| 裁切 | 取 `(430,120)-(1450,1140)`，缩放至 1020×1020 逻辑像素 |
| 去底噪 | 高斯背景归一化 + 硬阈值，抹掉扫描灰边与手写批注残留 |
| 提墙 | 先做水平/垂直方向开运算（只留长直段），再用 11px 方向闭运算**桥接扫描虚线**，最后栅格化成 256×256 的二值墙格（2 bit/格：细线 / 粗线） |

门洞（20–45 px）大于桥接半径，因此**不会被误填**——这是覆盖计算能区分房间的前提。

### 1.2 传播模型

```
RSSI = EIRP − PL(d) − Σ 墙损耗
PL(d) = 40.05 + 10·2.7·log10(d)     (2.4 GHz)
      = 46.42 + 10·3.2·log10(d)     (5 GHz)
```

墙损耗按「穿过的连续墙段」计数（双线墙只算一次），分外墙 / 内墙 / 窗三档：

| 预设 | 外墙 | 内墙 | 窗 |
|---|---|---|---|
| 轻质隔墙 | 6 dB | 3 dB | 2 dB |
| **砖墙（默认）** | **12 dB** | **6 dB** | **3 dB** |
| 承重墙 / 混凝土 | 20 dB | 12 dB | 4 dB |

5 GHz 的墙体损耗再乘 **1.55**（频率越高穿透越差）。

射线采样用「加厚墙」（每格取 3×3 邻域最大等级），否则斜射线会从 1 格厚的墙缝里漏过去，
热力图上会出现沿射线方向的条纹伪影。

### 1.3 速率换算

SNR → 802.11ax 2×2 MIMO MCS 表 → PHY 速率 × 带宽系数 → 吞吐取 50%。
所以你会看到 `1466 Mbps` 这种值——那是 160 MHz 下的理论物理层上限的一半，
**真实环境受干扰与空口竞争影响，通常还要再打 6~7 折**。

### 1.4 外墙 / 内墙判定

用 `data.js` 里的 `OUTLINE`（沿墙体中线走一圈的户型外轮廓多边形）：
距轮廓线 20 格以内、或落在轮廓之外的墙 → 外墙；其余 → 内墙。
这比「从图边界洪泛」可靠得多——后者会从入户门、阳台推拉门这类大开口漏进去。

## 2. 界面

### 平面热力图

- **拖动** AP / 终端改位置，松手即重算
- **滚轮** 缩放、拖空白处平移、**双击**复位
- 点 AP 卡片 → 弹出编辑面板，可改**信道 / 带宽 / 发射功率 / 启用开关**
- 左栏图层可单独关掉热力图、连线、房间标注、墙体

### 网络拓扑

自下而上的物理链路：`WAN → 主路由 → AP → 终端`。
有线回程是实线，无线回程是虚线；终端连线按 RSSI 上色。

### AP 位置推荐

点「搜索最佳 AP 补点位置」，在室内空地上按 32 px 步长枚举候选点，
逐个评估「加一台 23 dBm AP 后全屋平均 RSSI 提升 + 死角占比下降」，取前 5 名画在图上。

> 这是纯几何最优解，**不包含**「有没有网线 / 有没有插座 / 家具遮挡」这些现实约束。
> 实际选点时优先看有线回程可达性——无线回程会砍掉一半带宽。

### 导出报告

顶栏「导出报告」生成一份 Markdown，包含：AP 配置表、覆盖汇总、逐房间信号、
终端关联、信道规划、诊断建议，以及一张**实测数据回填表**。

回填表是给下一轮优化用的：把手机在各房间实测的 RSSI 填进去，
模型参数（墙损耗、EIRP）就能按实测反推校准，比默认值准得多。

## 5. 已知局限

1. **房间框是矩形近似**。不规则房间（如 L 形起居）会被切成矩形，边界处数值略偏。
2. **不建模家具、人体、金属**。实际贴墙的衣柜、玻璃隔断、金属门都会显著改变结果。
3. **不建模邻居 AP 干扰**。2.4G 的评估会偏乐观——实际同频干扰通常比模型严重。
4. **速率是理论上限的推算**，不代表实际测速。
5. 墙体来自扫描图自动提取，**门洞位置以图面为准**；如果图上门的位置和现场不符，覆盖结果会有偏差。

> 建议流程：先用默认参数看相对趋势（哪里弱、哪两个 AP 撞信道），
> 再用「导出报告」的实测回填表校准一次，之后以校准后的模型为准。

## 6. 用真实数据校准（推荐）

模型算的是「理论值」。要让拓扑图和 AP 位置**贴合你家实际情况**，
下面这条路比用手机 App 扫准得多。

### 6.1 为什么不用手机 App 扫

| 方案 | 能拿到什么 | 问题 |
|---|---|---|
| **手机浏览器网页** | ❌ 拿不到 RSSI | W3C 的 Network Information API 至今**没有任何主流浏览器**实现 `signalStrength`；iOS/Android 都不给 |
| **手机 App**（[NetSpot](https://www.netspotapp.com/help/wifi-site-survey-on-android/)、[WiFiman](https://help.ui.com/hc/en-us/articles/205204150-Using-WiFiman)） | 手机自己那一条链路的 dBm | 只能测「手机」这一台；要人举着手机走一圈，坐标还得手画；导出格式各家不同 |
| **路由器侧读取**（本项目） | **每台已关联终端在每个 AP 上的真实 dBm** | 只能看到「正在联网的设备」，看不到空房间 |

关键差异：路由器是**同时**从多个 AP 观测同一批设备，
这直接给出「同一终端到两个 AP 的功率差」，可以反解位置（见下）。

### 6.2 采集

```bash
cd netplan
python run_survey.py                 # 采一轮 → 定位 → 生成 geo.json
python run_survey.py --watch 60      # 每 60 秒一轮，适合让家人正常用网时长期观察
```

底层是两个脚本：

- `survey.py` —— 主路由走 SSH `iw dev <iface> station dump`，
  小米 AP 走 telnet `iwinfo <iface> assoclist`，合并成 `logs/survey.csv`
- `locate.py` —— 读 CSV，用双 AP 的 RSSI 差反解位置，导出 `geo.json`

实测一轮能拿到 **18~22 条**记录（含 IoT 设备），例如：

```
── ONT-5G (ch149/80MHz) ──
  MiAiSoundbox-LX06      -51 dBm   SNR 41
  Xiaomi-14-Pro          -71 dBm   SNR 21     ← 同时被 AP-5G 看到（-69）
── ONT-2.4G (ch6/20MHz) ──
  xiaomi-light-lamp35    -41 dBm   SNR 51
  roborock-vacuum        -46 dBm   SNR 46
```

### 6.3 定位原理与它的诚实边界

同一台终端在两台 AP 上的功率差只跟**距离比**有关：

```
RSSI_A − RSSI_B = 10·n·log10(d_B / d_A)      (n=3.2 @5GHz, 2.7 @2.4GHz)
```

这在平面上是**一条阿波罗尼斯圆弧，不是一个点**。所以：

- RSSI 差 **≥ 6 dB** → 圆弧很短，定位可靠（脚本标 `✓`）
- RSSI 差 **< 2 dB** → 圆弧横跨大半个户型，定位退化（脚本标 `✗`，网页画黄色 `?` + 虚线圆环）

`locate.py` 会同时给出 `spread_m`（候选点集跨度）和 `reliable` 标记，
**不会假装自己很准**。看到 `✗` 就让那台设备换个位置重采一次。

### 6.4 把实测灌进网页

网页左侧「导入 geo.json」→ 选 `geo.json`。之后：

- 实测定位的终端显示为**绿色实心 ✓**（可靠）或**黄色空心 ?**（退化）
- 不可靠的点外面画一圈虚线，半径 = `spread_m`，一眼看出可信范围
- 实测点与模型推算的位置对比，就能反过来校准 AP 的真实坐标

### 6.5 校准房间名和 AP 位置

顶栏切到 **「标定房间」**：

- 右侧列出 14 个房间，直接改名字（我原来起的「次卧（西北）」这类是按方位猜的）
- 点平面图上的房间选中，拖**四角手柄**改范围
- 点「保存」写进浏览器 localStorage，刷新后保留

**这一步是修正「房间名和设备摆放不准」最直接的办法** —— 
户型图是从扫描件自动提取的，但「哪个房间叫什么」「AP 到底摆在哪个角落」
只有住在里面的人知道。

### 6.6 进一步：用实测反推 AP 坐标

已知某台设备的确切位置（比如电视固定不动，你知道它在客厅某处），
用它和 AP 的实测 RSSI 可以反推 AP 坐标：

```
d = 10^((EIRP − RSSI − 墙损耗) / (10·n))
```

多个已知点做最小二乘即可。这条还没自动化——如果实测数据够多，
可以把它加进 `locate.py` 的 `--calibrate` 分支。

## 7. 点房间测信号（实时）

这是最接近你需求的功能：**在户型图上点一下，就记录这个位置此刻的真实信号**。

### 7.1 为什么需要一个本地服务

浏览器读不到 WiFi 的 RSSI（见 §6.1），所以必须由服务端去问路由器。
`server.py` 就是这座桥：

```
手机浏览器  --点击户型图-->  server.py  --SSH/Telnet-->  ONT + 小米 AP
     ^                          |
     +---- {rssi:-58, ap, ch} ---+
```

服务端用请求的**源 IP** 反查 DHCP 租约，就知道「是哪台设备在测」，
返回的正是你手里这台手机的 RSSI。

### 7.2 启动

```bash
cd netplan
python server.py                 # 默认 8787
python server.py --port 9000
python server.py --no-ap         # 只读主路由（快 3 秒，但看不到连在小米 AP 上的设备）
```

启动后终端会打印两个地址：

```
 本机:  http://localhost:8787/
 手机:  http://192.168.31.106:8787/   <- 用手机浏览器打开这个
```

**手机必须用局域网地址**，不能用 localhost。

### 7.3 用法

1. 手机浏览器打开上面的局域网地址
2. 左侧「实时信号」会显示**已连接**，并列出在线设备（每 8 秒自动刷新）
3. **在户型图上点任意位置** → 记录该点信号
4. 图上出现十字准星 + 数值，左侧显示完整信息（各 AP 的 ch/带宽/RSSI）

### 7.4 两个已知限制

| 现象 | 原因 |
|---|---|
| 本机（电脑上）点，提示「路由器看不到 127.0.0.1」 | 回环地址不在路由器的关联表里。**必须用手机**从局域网 IP 访问 |
| 手机点了提示「没找到对应设备」 | ① 手机用了**随机 MAC**（iOS/Android 默认开启）② 连的是 MIoT 隔离 SSID ③ 刚重连，租约还没更新 |

随机 MAC 是最常见的坑：iOS 在「无线局域网 → 该网络 → 私有无线局域网地址」里关掉，
Android 在「Wi-Fi → 该网络 → 隐私 → 使用设备 MAC」里改。改完重连一次即可。

### 7.5 实测记录怎么用

每次点击都会追加到 `S.measurePins`（图上打点）和 `S.measureLog`。
这些点比模型推算更可信 —— 它们就是你家真实的墙、真实的家具、真实的干扰。

后续可以拿这批点做**墙损耗标定**：同一房间的模型值 vs 实测值之差，
就是当前墙体预设的偏差量。差 6 dB 以上就该把墙材质从「砖墙」换成「承重墙」。
