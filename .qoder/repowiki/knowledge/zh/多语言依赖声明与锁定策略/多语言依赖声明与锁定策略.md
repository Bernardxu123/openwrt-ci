本仓库采用多模块、多语言的依赖管理方式，Go 后端与前端控制台各自维护独立的依赖清单与锁文件，未使用统一的 monorepo 工具进行跨语言聚合。

- Go 后端（notifuse/）：使用 go.mod + go.sum 声明依赖，Go 版本为 1.25.4；所有第三方包通过 require 显式列出，间接依赖以 // indirect 标注，未使用 replace 指令或私有代理，也未见 vendoring（无 vendor/ 目录）。
- Go 子模块（notifuse/telemetry/）：独立 go.mod，Go 版本为 1.24.0，仅依赖 Google Cloud Functions SDK 与 logging，与主模块解耦。
- React 控制台（notifuse/console/）：使用 package.json + package-lock.json（lockfileVersion 3），通过 overrides 字段集中修复安全漏洞（如 fast-xml-parser、markdown-it、minimatch、yaml 等），并包含一个自定义脚本 bundle-liquid 将 liquidjs 浏览器版复制到 Go 侧 pkg/liquid/ 供服务端渲染使用。
- 通知中心（notifuse/notification_center/）：另一个独立的 Vite + React 应用，拥有自己的 package.json，与 console 共享类似技术栈但独立依赖。

关键约定：
- Go 依赖全部使用精确的 commit SHA 或语义化版本，避免浮动版本导致构建不一致。
- 前端通过 overrides 统一收敛下游依赖的安全补丁版本，减少漏洞扫描噪音。
- 前后端之间唯一的“共享”依赖是 liquidjs，通过构建脚本在编译期复制产物到 Go 包中，而非通过 npm 包发布。
- 未发现 GOPRIVATE、私有 Go module proxy 或 Go vendor 配置，依赖均从公共 Go 代理与 npm registry 拉取。
