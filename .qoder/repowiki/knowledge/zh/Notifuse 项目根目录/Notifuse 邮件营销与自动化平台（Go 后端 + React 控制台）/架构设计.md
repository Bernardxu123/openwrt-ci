模块采用经典的分层架构，由 `cmd/api/main.go` 作为唯一可执行入口，通过 `internal/app.App` 装配依赖并启动 HTTP 服务器；内部按职责划分为：
- `config/`：基于 viper 的环境/数据库配置加载，区分运行时环境变量与持久化设置。
- `internal/domain/`：纯 Go 领域模型与接口定义（Repository/Service 接口），不含外部依赖，是各层契约边界。
- `internal/repository/`：PostgreSQL 实现，使用 `github.com/Masterminds/squirrel` 构建 SQL，并通过 `pkg/database.ConnectionManager` 在多工作区 DB 间路由连接。
- `internal/service/`：业务编排层，组合多个 repository 与第三方服务（SES/SendGrid/Mailgun/Postmark/SparkPost/SMTP），并注册到 `service.TaskScheduler` 与 `queue.EmailQueueWorker` 等后台处理器。
- `internal/http/`：HTTP handler，每个领域一个文件（如 `broadcast_handler.go`），统一经 `app.mux` 注册，配合 `internal/http/middleware/` 做鉴权、限流、追踪。
- `internal/migrations/`：按 `vN.go` 编号的迁移脚本，由 `migrations.Manager` 在启动时自动运行，支持“需重启”信号。
- `pkg/`：跨应用的可复用库（mailer、smtp/smtp_bridge 服务器、liquid 模板渲染、MJML 转换、OpenCensus tracing、rate limiter、bot detection 等）。

前端部分包含两个独立的 Vite+React 应用：`console/` 为完整的管理控制台（Playwright E2E + Vitest 单元测试），`notification_center/` 为轻量通知中心组件，二者均通过 OpenAPI 规范（`openapi/` 目录 YAML 分片，`Makefile openapi-bundle` 生成 `openapi.json`）与后端交互。`telemetry/` 是独立 Go Cloud Function，负责将遥测数据写入 BigQuery。
