- 领域层以 `*_repository.go` / `*_service.go` 成对定义接口与实现，接口位于 `internal/domain/*_repository.go`，具体 Postgres 实现在 `internal/repository/*_postgres.go`。
- HTTP handler 按资源一文件一结构体组织（如 `BroadcastHandler`），并在 `app.InitHandlers()` 中集中注册到 `http.ServeMux`，错误统一经 `http/utils.go` 的响应辅助函数返回。
- 所有对外部系统的调用（邮件提供商、LLM、Supabase、Webhook）都通过 `domain` 层定义的接口抽象，`internal/service` 构造时注入，便于测试替换。
- 配置项通过 `config.Config` 结构体 + viper 读取，新增字段需在 `EnvValues` 中同步标注来源以便 setup wizard 识别哪些值来自真实环境变量。
- 数据库迁移以 `vN.go` 命名并按版本号递增，每个迁移文件自带 `_test.go`，由 `migrations.NewManager` 在 `InitDB` 阶段顺序执行。
- 测试普遍使用 `github.com/stretchr/testify` 与 `github.com/DATA-DOG/go-sqlmock`，并通过 `internal/domain/mocks/` 下的 gomock 生成文件替代领域接口。
