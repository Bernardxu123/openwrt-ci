## B. 包内：DTB 里逐字存在 PR #34 后的 compatible

从 CT sysupgrade 包 FIT 的 `fdt-1`（23,281 字节）解析出的节点：

```
/soc/switch@1fb58000/mdio/ethernet-phy@7
    compatible = "ethernet-phy-id67c9.de10"     ← PR #34 之后的写法
    reg = <7>
    reset-gpios = <&{/soc/system-controller@1fbf0200/pinctrl} 0x22 0x1>   ← pin 34, ACTIVE_LOW
    reset-assert-us = 100000
    reset-deassert-us = 100000
/soc/ethernet@1fb50000/ethernet@4
    openwrt,netdev-name = "lan1"
    phy-handle = <0x3d>            ← 指向上面这个 phy@7
    phy-mode = "2500base-x"
    status = "okay"
/soc/pcs@1fa09000  status = "okay"   ← 2500base-x PCS 使能
/soc/switch@1fb58000/ports/port@1  status = "disabled"   ← 内建 PHY1 关闭
/soc/switch@1fb58000/mdio/ethernet-phy@9  status = "disabled"
```

同版本 CU 包 DTB 中：`ethernet-phy@7` 节点**不存在**，`ethernet@4` 为 `disabled`，
`port@1`（lan1）`status = "okay"` + `ethernet-phy@9` `okay`（内建 PHY1 接管 lan1）。

## E. 反面对照：QWRT CT 包里的 DTB 是"修复前"状态

从 QWRT CT 包内 `fdt-1`（14,698 字节）解析：

```
/mdio@1fb5f01c/ethernet-phy@7
    compatible = "ethernet-phy-ieee802.3-c45"     ← 旧写法（无显式 PHY ID）
    reg = <7>
    reset-gpios = <&{/syscon@1fbf0200} 0x22 0x1>   ← pin 34
    reset-assert-us = 100000
    reset-deassert-us = 800000                     ← 800 ms（ponwrt 为 100 ms）
```

→ QWRT 这个 CT 包构建于更早的 BSP/时点，**没有 PR #34 的显式 ID 修复**；
反过来说明"包内有无 `ethernet-phy-id67c9.de10` 字符串"确实能区分修复前后。

## 推断（不是包内证据）

PR #34 的动机（"warm reboot 后 C45 ID 探测遇到 PHY 仍在复位 → 绑定 Generic C45 PHY
→ lan1 NO-CARRIER 直到冷启动"）出自 PR 描述与 dtsi 注释本身；本机**没有做过**
CT 硬件上的 warm/cold reboot 对比实验，因此"该修复在真机上消除了 lan1 冷启动才通的问题"
属于**未在本机复现**的结论。
