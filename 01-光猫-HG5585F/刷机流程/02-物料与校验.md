| 文件 | 字节 | 归属 |
|---|---:|---|
| `mtd13-factory.bin` | 3,145,728 | 本机 **CU**（联通）机备份 |
| `factory-1m.bin` | 1,048,576 | 同上，由 factory 转出的 1 MiB 镜像 |

- **必须在 CT 实机上现场生成**：原厂 root shell → 跑 `an758x-stock2ubi` → 浏览器开 `http://<CT的IP>:3333/` → 逐分区下载（**mtd13 factory 必下**）→ 用 `fiberhome-factory.exe` 转成 1 MiB → ponwrt 首启时上传作 **PON board data**。
- **为什么必须要**：`mtd13 factory` 内含 PON 身份 + **APONCAL 光模块校准（2 KB @0x0）** + **MT7916 WiFi EEPROM（4 KB @0x1000）** + `base_mac`/`pon_sn`/`device_sn`。缺 APONCAL → **PON 起不来**；缺 EEPROM → **WiFi 起不来**；且这些是**每台机器唯一**的校准数据，别人的备份刷进去等于用错校准值（后果未验证，但按校准数据性质不应混用）。
- ⚠️ 拿 CU 机的 `mtd13` 去喂 CT 属于**跨机型混用身份数据**，本文明确**不推荐**，也不再展开。

## 5. ⚠️ 命名坑（下错 = 砖）

三个层面各用一套写法，**同一台机器在三处名字不一样**，这是最容易下错包的地方：

| 场合 | 写法 | 实例 |
|---|---|---|
| Release 资产名 / 引导文件名 | **连字符** `hg5585f-ct` | `an7581-fiberhome-hg5585f-ct-firstblock.bin`、`...-ct-bl31-u-boot.fip` |
| ponwrt 镜像名 / profile 名 | **下划线** `fiberhome_hg5585f-ct` | `ponwrt-airoha-an7581-fiberhome_hg5585f-ct-squashfs-sysupgrade.itb`；`profiles.json` 内 profile 键 = `fiberhome_hg5585f-ct` |
| OpenWrt `supported_devices` / DTB compatible | **逗号 + 连字符** `fiberhome,hg5585f-ct` | `profiles.json` 的 `["fiberhome,hg5585f-ct","fiberhome,hg5585f-ct-usb-sfp"]` |

**绝对不能把 `-cu` 包刷到 CT**（反之亦然）。工作区 `光猫-HG5585F\downloads\` 里 CU 件就躺在 CT 件隔壁，务必按名字 + sha256 双确认：

| 机型 | 系统镜像 | 字节 | SHA256 前 16 |
|---|---|---:|---|
| **CT** | `..._hg5585f-ct-squashfs-sysupgrade.itb` | 60,727,597 | `7d04c755584bccb8` |
| CU | `..._hg5585f-cu-squashfs-sysupgrade.itb` | 60,723,501 | `192270bd8db11eb4` |
| **CT** | `..._hg5585f-ct-initramfs-recovery.itb` | 53,608,448 | `5978cbb640d8dbbe` |
| CU | `..._hg5585f-cu-initramfs-recovery.itb` | 53,608,448 | `777812b68c857ac1` |

> 🔴 **实测警告：CT 与 CU 的 initramfs 字节数完全相同（都是 53,608,448 B）**，sysupgrade 也只差 4,096 B。**光看大小分辨不出来**，必须看文件名或比对 sha256。
> 另一层：QWRT 分析报告实测 CT 与 CU 的差异在 **`lan1` PHY 接法**（CT 用外置 GPY211C 2.5G，CU 全板载 PHY1/2/3/4，CU 无 `gdm4`）。刷错机型不是"大不了重刷"，是**直接没网口**。

## 7. QWRT 包（当前主目标）的事实与风险

`物料\可选-QWRT\QWRT-R26.10.18-...-ct-...itb`（42,152,775 B / `5053531f30dc9abc`）是 CT 原生的第三方重打包 QWRT。已核对：

- 内容为 OpenWrt **25.12.3** / `r7856-44e450dae4` / kernel **5.4.302**；FIT 三分区 crc32+sha1 全过，`fwtool_signature: true`；
- 签名体系是 **本地 build key**（key id `215087f5c3341288`），**不是**运营商/官方发布签名；
- 白名单 `supported_devices = ["fiberhome,hg5585f-ct","fiberhome,hg5585f-ct-usb-sfp"]`，**在 CT 机上不需要 `-F`**；
- 2026-10-21 把它的 rootfs 拆开核对（详见 `08`）：`02_network` 把 **lan1 当 WAN、lan2-4 当 LAN**；默认 LAN `192.168.1.1`；`97-default-settings` 设 root 密码 `password`；`S50telnetd` **Telnet 默认开**；`rtwifi.sh` 生成 WiFi 时 **`encryption=none`（开放）**；`pon.line0.mode` 为空、`operator=ctc`、`ge_ports=1`；**没有 Passwall**；首启 `13_opkg_update` 会把 feeds 改成 **ImmortalWrt 24.10.6**（与 25.12.3 镜像不匹配）。

> **2026-10-21 19:36 追加（R26.10.21 实刷）**：新包 `QWRT-R26.10.21`（42,201,767 B / `8592e57a…`）已实刷成功，**修复了 R26.10.18 的 PON OAM 兼容问题**（新 `airoha-pond` `d6974f7b…`）；PON 认证 `accepted`、PPPoE/IPv6/WiFi/5G 160MHz 全部实测通过。新固件默认 `pon` 配置**缺 `operator='ctc'`**，必须按 `08` 新块补；PON MAC/SN 需按现网 CU 光猫克隆（只克隆 MAC+SN，不改 CT factory 校准）。详见 `数据模板/刷机记录.md` §6。

**风险（已在 `08` 展开）**：
- QWRT 的 DTB 仍是 PR #34 **之前**的写法（`ethernet-phy-ieee802.3-c45`、800ms 复位）→ 暖重启 `lan1` 可能 NO-CARRIER；
- reset 键 DTB 指向 **GPIO0**（实际 GPIO35）→ 内核侧按键可能无效；
- 老内核 5.4.302，不能套用 ponwrt 6.18 的驱动经验；
- 默认开放 WiFi、默认 lan1=WAN、默认 LAN `192.168.1.1`，首启必须逐项改；
- 没有 Passwall，现网分流不能直接搬。

**结论**：QWRT 在 CT 上是**原生可用**的，刷机流程见 `08-QWRT刷机流程.md`；上述风险都是“需要手工处理/接受”的代价，不是“不能刷”。

### 8.2 硬件

| 硬件 | 规格 | 说明 |
|---|---|---|
| **USB-TTL 串口线** | **必须 3.3V 电平**，115200 8N1 | 拆机焊/夹 3 根（TX/RX/GND）；**5V 电平接到 3.3V 板上可能打坏芯片**，接线前先用万用表确认电平 |
