# 03 · 身份采集与备份（刷机前唯一不可重来的一步）

> 目的：在动任何固件之前，把 **CT 机的身份数据**和**原厂 17 个 MTD 分区**完整落到 PC 上。

## 2. 四条访问路线（按侵入性从低到高）

| 路线 | 前提 | 能做什么 | 风险 |
|---|---|---|---|
| **W1 原厂 Web 后台** | 超管口令 | 看信息、改配置、固件升级（原厂包） | 低 |
| **W2 `/fh_tool/api`** | 知道 MAC，或从 `web_get_brmad` 自动读 | 只读 `GetDevInfo`/`GetTelnetInfo`；写 `TelnetEnable` | 低（只在 LAN 内） |
| **W3 Telnet（opuser/root）** | W2 开 telnet + CT V2 默认 `telnetadmin`/`FH-nE7jA%5m`+MAC6（或 CU 的 `admin`/`Fh@…`） | 读文件、`load_cli factory`、改 `/tmp/shadow` | 低-中（受限 shell） |
| **W4 TTL 串口** | 拆机接 3 根线 | root shell（改 shadow 后）、看启动日志 | 中（要拆机） |

> `/fh_tool/api` 的 AES 只是**报文编码**，不是身份认证；密钥由 MAC 派生。只在自家 LAN 用，别暴露公网。

### 2.1 W2 用法

```powershell
# 最省事：不传 MAC，脚本自动从设备的 web_get_brmad 读（只读、无鉴权）
python .\脚本\fhtool-ct.py 192.168.1.1

# 也可以手动给 MAC
python .\脚本\fhtool-ct.py 192.168.1.1 <MAC12>
```

脚本会：
- 用 `sha256(MAC12)` 派生 key/iv（与既有 CU 工具、以及共享的 CT V2 工具**同一算法**）
- 依次尝试 `http://IP:8080/fh_tool/api` 和 `http://IP:80/fh_tool/api`（**CT V2 默认 8080**；CU 是 80）
- 先 `GetDevInfo`（所有固件都有），再可选 `GetTelnetInfo`
- 不给 MAC 时先 GET `/cgi-bin/ajax?ajaxmethod=web_get_brmad`，读 JSON 的 `.brmad`

若要开 telnet（写操作，**只写运行时、不持久化**）：

```powershell
python .\脚本\fhtool-ct.py 192.168.1.1 --telnet-on
```

### 2.2 W3 登录

```powershell
telnet 192.168.1.1
# CT V2 默认：telnetadmin / 'FH-nE7jA%5m' + MAC 后六位   ← 共享工具静态证据
# CU/旧固件： admin       / 'Fh@' + MAC 后六位（末位 0 或无效时试 +1）
```

> CT V2 的口令规则来自 `HG5585F-CT-V2一键开Telnet.exe` 的常量（`telnetadmin`、`'FH-nE7jA%5m'`、MAC[-6:]），见 `分析/共享资料评估.md`；属静态证据，实机若已改口令则失效。

登录后先确认环境：

```sh
cat /proc/self/status | grep -i -E 'Uid|Gid|CapEff'
cat /proc/mtd
cat /proc/sys/kernel/osrelease
cat /proc/consoles
```

CU 机的实测值是：`Uid: 100`、`CapEff: 0`、无 SUID、`osrelease=5.4.55`、`consoles=ttyS0`。CT 若不同，记录下来。

### 2.2.1 隐藏账户 / 工厂 CLI（社区方法，未在本机复现）

烽火机型常见做法（电信版尤其）：

1. Telnet（opuser）里执行：`echo 1 > /var/fhconfig`（等价 `touch /var/fhconfig`；`/var` 指向 `/tmp`，可写）。
2. 浏览器开 `http://192.168.1.1`，用隐藏账户 `fiberhomehg2x0` / `zgjt` 登录（恩山帖说法；也有人反馈该口令不对，随固件而异）。
3. 后台「预配置」可看/改运营商与地区；工厂 CLI 里 `load_cli factory` → `show admin_name` / `show admin_pwd` 读超管。
4. 注意：这一步是**读超管/看配置**，不是拿 root；改运营商/地区会影响 TR069 下发，刷机前没必要动。

> 来源：恩山帖 <https://www.right.com.cn/forum/thread-8412912-1-29.html>（外部资料，未在本机复现）。

### 2.3 W4 串口接线

- USB-TTL 设 **3.3V**；只接 `TX`/`RX`/`GND`，**不接 VCC**。
- 交叉：`TTL TX → 猫 RX`，`TTL RX ← 猫 TX`。
- 波特率 **115200 8N1**，无流控。
- 抓日志：
  ```powershell
  pwsh -File .\脚本\serial-capture.ps1
  ```
  脚本自动挑非蓝牙 COM 口；也可 `-Port COM7`。
- 上电应看到 BL2 → U-Boot → Linux → `login:`。

## 3. Telnet 受限 shell 生存指南（CU 实测，CT 可能不同）

- **按命令名黑名单**：拦 `dd` `rm` `cp` `ln` `head` `uname` `which` `id` `df` `wget`；放行 `ls` `cat` `echo` `grep` `wc` **`mv`** `tar` `sed` `openssl` 以及 `/fhrom/bin/*` 绝对路径。
- 因此：
  - 传文件用 `/fhrom/bin/wget`（GNU Wget 1.21.4），不要用裸 `wget`。
  - 需要 `cp` 时用 `cat a > b` 或 `mv`。
  - 需要 `id` 时用 `cat /proc/self/status`。
- **`/var` 和 `/etc/{passwd,shadow}` 都是指向 `/tmp` 的符号链接**；`/tmp` 是 **777 且无 sticky 位** → `mv -f` 的 `rename()` 能覆盖 root 拥有的文件。这是改 root 口令的技术前提。
- `/tmp` 是 tmpfs：**重启即还原**。

## 4. 拿 root 的三条路（详见 `01` 阶段 2）

### 4.1 `su`（最快，CT 可能可用）

```sh
su
# 密码候选：Fh@<MAC6>、Fh@<MAC6+1>、贴纸超管密码、
#           telecomadmin / nE7jA%5m / admintelecom、
#           CT V2 的 'FH-nE7jA%5m'+<MAC6>
id    # uid=0 即成功
```

### 4.2 改 `/tmp/shadow` → 串口 root（CU 的设计路线）

**自动**（推荐先试）：

```powershell
python .\脚本\ont-setrootpw-ct.py --ip 192.168.1.1 --user admin --pass "Fh@123456" --status
python .\脚本\ont-setrootpw-ct.py --ip 192.168.1.1 --user admin --pass "Fh@123456" --set --password "Ct@Test2026"
```

脚本会：读 shadow → 用设备 `/fhrom/bin/openssl passwd` 生成同 salt 哈希 → `sed` 写 `/tmp/shadow.new` → `mv -f` 覆盖 → 回读校验。

**手动兜底**（设备没有 openssl 时）：

1. 先读原哈希，记下算法和 salt：
   ```sh
   cat /etc/shadow
   # root:$1$XXXX$...:...    → 算法 1（MD5）或 6（SHA-512），salt=XXXX
   ```
2. PC 上生成同 salt 哈希（Git for Windows 自带 openssl）：
   ```powershell
   & "C:\Program Files\Git\usr\bin\openssl.exe" passwd -6 -salt <SALT> "Ct@Test2026"
   # 算法与设备一致：$1$ 用 -1，$5$ 用 -5，$6$ 用 -6
   ```
3. telnet 里替换（注意用 `|` 作分隔符，哈希里的 `/` 不用转义）：
   ```sh
   cat /etc/shadow | sed 's|^root:[^:]*:|root:<粘贴哈希>:|' > /tmp/shadow.new
   mv -f /tmp/shadow.new /tmp/shadow
   cat /etc/shadow
   ```
4. 串口 `login:` 用 `root` + 新口令登录，`id` 验证。

> 若串口 login 仍拒绝：检查 `/etc/passwd` 里 root 的 shell 是否是 `/bin/sh`（不是 `/sbin/nologin`），以及 `/etc/shadow` 是否真的被替换（`ls -l /etc/shadow`）。

### 4.3 原厂一键包（有 CT 版包时最省事）

拿到 CT 版 `Fh-HG5585F-Ubi-Update-…-CT.bin` 后：恢复出厂 → 默认超管 → 原厂固件升级页刷包 → 重启后 `http://192.168.1.1:3333/` 直接是 root 的 stock2ubi 页面。此时**跳过 4.1/4.2**，直接进第 5 节。

## 7. factory 3 MiB → 1 MiB（关键）

### 7.1 为什么不能直接截断

ponwrt 的 `03_pon_data` 要求 1 MiB 的 `factory` 卷；原厂 `mtd13` 是 3 MiB，且**内部不是裸偏移布局**：

- CU 实测：原始 `mtd13` 在 `0x2000`（MAC）、`0x2010`（PON SN）、`0x2020`（设备 SN）全部是 `FF`。
- 身份数据在分区内部的 UBI/UBIFS/厂商容器里，必须由 `fiberhome-factory` 解析后重排。

### 7.2 操作

1. 运行 `物料\工具\fiberhome-factory.exe`。
2. 打开/拖入 `mtd13-factory.bin`（3 MiB）。
3. 工具会显示解析出的组件：
   - APONCAL（PON 光模块校准，2 KB）
   - MT7916 EEPROM（WiFi，4 KB）
   - Base MAC
   - PON serial number
   - Device serial number
4. 核对 MAC/SN 与贴纸一致。
5. 保存为 `factory-1m.bin`，大小必须 **1,048,576 字节**。

> 如果导入失败：确认选的是「stock / unified factory image」而不是 UBI 卷；也可尝试把 `mtd13` 先按 UBI/UBIFS 方式打开。工具 README 明确支持 stock UBI/UBIFS、JFFS2、unified factory 三种输入。

### 7.3 校验（抄自 CU 实测布局）

| 偏移 | 长度 | 内容 | 期望 |
|---|---|---|---|
| `0x000000` | 2 KB | APONCAL | 开头 ASCII `APONCAL` |
| `0x000800` | 2 KB | 保留 | — |
| `0x001000` | 4 KB | MT7916 EEPROM | 前 2 字节 `16 79` |
| `0x002000` | 6 B | Base MAC | 与贴纸一致 |
| `0x002010` | 8 B | PON SN | `FHTT` + 8 hex |
| `0x002020` | 32 B | 设备 SN | 与贴纸一致（ASCII） |

```powershell
$f = "备份\原厂-YYYYMMDD\factory-1m.bin"
function HexAt($p,$off,$len){ $fs=[IO.File]::OpenRead($p); $fs.Position=$off; $b=New-Object byte[] $len; [void]$fs.Read($b,0,$len); $fs.Close(); ($b|%{$_.ToString('x2')}) -join ' ' }
"size = $((Get-Item $f).Length)"
HexAt $f 0x0 16; HexAt $f 0x1000 2; HexAt $f 0x2000 6; HexAt $f 0x2010 8; HexAt $f 0x2020 32
```

**五项全对才算过。** 不对就重转，不要带着错镜像写板级数据。

## 9. 采集失败排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `192.168.1.1` 打不开 | PC 不在同网段 / 光猫没 DHCP | PC 设 `192.168.1.10/24`；换 LAN2；换网线 |
| 超管口令全错 | 卖家改过 / 不是默认 | 恢复出厂（Reset 10s）再试贴纸；问卖家 |
| `fhtool-ct.py` 连接失败 | 端口不对 / API 关闭 | 80/8080 都试；先确认 Web 能开；看 `GetTelnetInfo` 是否 `result:0` |
| API 返回解密失败 | MAC 抄错（大小写/位数） | 用 12 位 HEX，去掉 `:`/`-`；与贴纸逐位核对 |
| Telnet 登录失败 | 口令规则不同 | 试 `Fh@`+后六位、+1、贴纸超管；确认 23 端口开 |
| `su` 全错 | CT 固件也封了 | 走串口路线 |
| 串口无输出 | TX/RX 反了 / GND 没接 / 5V 电平 | 交叉 TX/RX、共地、确认 3.3V |
| `login:` 后 root 拒绝 | shadow 没替换成功 / shell 不对 | 回读 `/etc/shadow`；检查 `/etc/passwd` |
| stock2ubi 报版本 | 内核不是 5.4.55 | `--ignore-kernel-version`（先备份，风险自担） |
| `:3333` 打不开 | 进程退出（telnet 超时）/ 防火墙 | 串口重跑；确认监听；PC 防火墙放行 |
| 分区下载 0 字节 | 浏览器/杀软拦截 | 换 Edge/Chrome；关下载拦截；重试 |
