> 适用：**烽火 HG5585F-CT（电信版，2.5G 口）** ｜ 目标固件：**ponwrt v2026.10.18 CT**
> ⚠️ **这是 ponwrt 备选线**；你已决定刷 QWRT 的话，主线看 `08-QWRT刷机流程.md`（阶段 0–3 的准备/备份/写引导与本文相同）。

## 阶段 1 · 原厂状态采集（只读，15 分钟）

> 目标：确认「能不能刷」和「它是谁」。**这一阶段不写任何东西。**

**1.1 单独上电，进原厂后台**

- 网线接 **LAN2**（不要用 2.5G 的 LAN1，保持和后面 U-Boot 阶段一致的习惯）。
- PC 网卡设自动获取。若拿不到地址，手动设 `192.168.1.10/24`、网关 `192.168.1.1`。
- 浏览器开 `http://192.168.1.1`。
- 默认超管候选（**以贴纸/卖家说明为准**，逐个试，别锁号）：
  - 电信通用：`telecomadmin` / `nE7jA%5m`
  - 贴纸上的「默认用户名/密码」
  - 联通通用（如果这台其实刷过 CU 固件）：`CUAdmin` / `CUAdmin`
  - 普通用户：`user` / 贴纸密码
- 如果进不去：断电，按住 Reset 10 秒恢复出厂，再用贴纸默认口令。

**1.2 记录原厂信息**（截图 + 抄进 `数据模板/identity-ct.json`）

- 设备型号/硬件版本/软件版本/编译时间（状态页或「设备信息」）
- 设备标识号（通常 `OUI-` + 32 位 SN）
- PON SN / MAC / LOID（「网关注册信息」或「PON 信息」）
- 用户侧以太网口信息（确认 **4 个口**：1×2.5G + 3×GE）
- 默认 Wi-Fi SSID/密码

**1.3 用 `/fh_tool/api` 读机器信息（只读）**

```powershell
# 最省事：不传 MAC，脚本自动从 web_get_brmad 读（只读、无鉴权）
python .\脚本\fhtool-ct.py 192.168.1.1

# 也可以手动给 MAC（贴纸/后台，去掉冒号/横线）
python .\脚本\fhtool-ct.py 192.168.1.1 A1B2C3D4E5F6
```

它会按 **8080 → 80** 尝试（CT V2 默认 8080；CU 机是 80），先 `GetDevInfo` 再可选 `GetTelnetInfo`，打印解密 JSON。

重点看：
- `current_ponmode`：**必须是 `EPON_10G`**（= ponwrt/QWRT 的 `epon-10g-1g`）
- `port_num`：应为 `4`
- `hardwareversion` / `softwareversion`：CT V2 共享工具的闸门是 `V4.2.0` / `24FHW45000`，记下来
- 型号串/硬件版本

> **决策门 A**：
> - `EPON_10G` → 继续。
> - `GPON` / `XGPON` / `EPON_1G` → **停**。ponwrt 的 AN7581 驱动只实现了 10G-EPON；刷了 PON 也不工作，只能当普通路由器/AP。是否继续由你决定（当路由器也有价值，但本包的 PON 章节全部作废）。

**1.4 打开 Telnet（为拿 root 铺路）**

```powershell
# 写操作：只开运行时 telnet，不持久化、不重启
python .\脚本\fhtool-ct.py 192.168.1.1 --telnet-on
```

然后：

```powershell
# 手动 telnet 登录（Windows 自带客户端可能没装，用 PuTTY / plink / python 均可）
telnet 192.168.1.1
# CT V2 默认：telnetadmin / 'FH-nE7jA%5m' + MAC 后六位
# CU/旧固件： admin       / 'Fh@' + MAC 后六位（末位 0 或无效时试 +1）
```

> CT V2 的口令规则来自共享 `HG5585F-CT-V2一键开Telnet.exe` 的常量（静态证据，见 `分析/共享资料评估.md`）；实机若改过口令则失效。
> 社区规则是「MAC 后六位，末位 0 或无效时 +1」；CU 机实测是**原样不加 1**。所以两种都试。
> 登录后若 `id` 是 **root**，直接跑 stock2ubi，**无需拆机**；若是 `opuser`（uid 100），能 `cat/ls/echo/grep/mv/sed`，不能 `dd/cp/rm/id/df/wget`（裸命令名被拦；`/fhrom/bin/wget` 可放行），需继续 `su` 或串口路线。

**1.5 工厂 CLI 只读采集**（可选但建议）

Telnet 里：

```sh
load_cli factory
show allinfo
show admin_name
show admin_pwd
```

把输出抄进 `数据模板/identity-ct.json`。若命令不存在/报错，跳过。

**1.6 判据**

- [ ] 能进原厂后台
- [ ] `current_ponmode = EPON_10G`
- [ ] MAC / PON SN / 设备 SN 已记录
- [ ] Telnet 能登录（至少到 opuser）

## 阶段 2 · 拿 root（30–90 分钟，可能拆机）

> 目标：拿到 uid=0，才能跑 `stock2ubi`（它必须 root）去备份分区、写引导。
> 按顺序试，**任何一步成功就停**。

### 路线 A · 原厂「一键刷入包」（最省事，但 CT 版包目前没有）

CU 机 2026-10-19 的备份/写引导就是在 `:3333` 页面完成的；原厂一键包的操作说明描述的正是这条形态：恢复出厂 → 默认超管 → 原厂「固件升级」页 → 刷 `Fh-HG5585F-Ubi-Update-1h-V260921-1.bin` → 设备重启后 `http://192.168.1.1:3333/` 直接是 stock2ubi 页面（**已经以 root 跑**）→ 备份 + 写引导。

**CT 现在缺这个包。** 不要拿 CU 的包硬刷。向卖家/QQ 群（1020152066）要「HG5585F 电信版 原厂后台一键刷入包」，拿到后放 `物料/工具/`，流程照 CU 的做（见 `02` 的补料说明）。
> 这条路线一旦有了包，阶段 2 直接跳过，阶段 3 从 `:3333` 开始。

### 路线 B · Telnet `su`（CT 可能可用，先试）

Telnet 登录 opuser 后：

```sh
su
# 密码候选（逐个试，别连续错太多次）：
#   Fh@ + MAC 后六位（原样）
#   Fh@ + MAC 后六位（末位 +1）
#   telecomadmin / nE7jA%5m / 贴纸超管密码
```

成功后：

```sh
id
# 期望：uid=0(root) gid=0(root)
```

> CU 机实测：`su` 存在但上述密码全部 `incorrect password`，改 `/etc/shadow`、`/var/tel_passwd` 也无效 → CU 走不通。
> CT 是否可走通**未验证**，值得先试 5 分钟。

### 路线 C · TTL 串口 + 改 shadow（兜底，CU 的设计路线）

原理：串口 getty 是**标准 busybox login**，只读 `/etc/passwd` + `/etc/shadow`；而 `/etc/shadow` 是指向 `/tmp/shadow` 的符号链接，`/tmp` 是 777 且**无 sticky 位** → 用 `mv -f` 的 `rename()` 可以整体替换 root 拥有的文件。telnetd 那套私有校验不认，但串口 login 认。

**C1 接串口**

- 光猫断电，接 3 根线：`TTL TX → 猫 RX`、`TTL RX ← 猫 TX`、`GND ↔ GND`。**不接 VCC**。
- PC 打开抓取脚本（自动选 COM 口，日志写 `日志/`）：

```powershell
pwsh -File .\脚本\serial-capture.ps1
```

- 给光猫上电。正常会依次看到 BL2 → U-Boot → Linux 启动日志 → 最后停在 `login:`。

**C2 改 root 口令（在 telnet opuser 里做，不需要串口登录）**

```powershell
# 先看状态（只读）
python .\脚本\ont-setrootpw-ct.py --ip 192.168.1.1 --user admin --pass "Fh@123456" --status

# 改口令（会先备份到设备 /tmp/shadow.ontbak 和本地 备份/）
python .\脚本\ont-setrootpw-ct.py --ip 192.168.1.1 --user admin --pass "Fh@123456" --set --password "Ct@Test2026"
```

脚本逻辑：读 `/etc/shadow` 的 root 哈希算法/salt → 用**设备自带** `/fhrom/bin/openssl passwd` 生成同 salt 新哈希 → `sed` 写入 `/tmp/shadow.new` → `mv -f` 覆盖 → 回读校验。
> 若 CT 没有 `/fhrom/bin/openssl`，脚本会在第 3 步报错；此时改用本地 openssl 生成哈希（见 `05` 的备用命令），其余步骤不变。

**C3 串口登录 root**

在串口窗口 `login:` 后输入 `root` + 刚设的口令：

```sh
id
# 期望 uid=0(root)
cat /proc/sys/kernel/osrelease
cat /proc/consoles
```

> ⚠️ `/tmp` 是 tmpfs，**一重启就还原**。`改口令 → 串口登录 → 跑 stock2ubi 备份/写引导`必须在**同一次开机**内完成，中途别断电。

**C4 注意**

- 串口登录后**不要**在 telnet 里再操作；所有后续命令都在串口 root shell 里做。
- 若串口没有任何输出：检查 TX/RX 是否交叉、GND 是否接好、波特率是否 115200 8N1、USB-TTL 是否 3.3V。

### 路线 D · 只差 FIP 时的串口 XMODEM（阶段 4 用）

如果你已经用 stock2ubi 写了 `firstblock`，但 `:3333` 页面传 fip 失败/没反应，重启后 BL2 会提示按 `x` 走 XMODEM。此时用：

```powershell
pwsh -File .\脚本\xmodem-send-fip.ps1 -Port COM7
```

默认发送 `物料/引导/an7581-fiberhome-hg5585f-ct-bl31-u-boot.fip`。详细时序见阶段 4 的「路线 2」。

### 判据

- [ ] 某个 shell 里 `id` = `uid=0(root)`
- [ ] 能读 `/dev/mtd13`（`cat /dev/mtd13 | wc -c` 应约 3145728，或 `ls -l /dev/mtd13` 有权限）

## 阶段 3 · 全分区备份 + factory 1MiB（30–60 分钟）

> **这是全流程唯一不可重来的步骤。** 原厂 CT 固件官方不提供下载，备份就是你唯一的回滚来源。

**3.1 把 stock2ubi 送进光猫 `/tmp`**

PC 上起一个临时 HTTP 服务（**新开一个 PowerShell 窗口，别关**）：

```powershell
cd D:\AI\路由\光猫-CT-HG5585F\物料\工具
python -m http.server 8000
# 记下本机 IP（另一窗口 ipconfig），假设 192.168.1.10
```

在光猫的 root shell（串口或 telnet root）里：

```sh
# 注意：受限 shell 会拦裸 wget，必须用绝对路径
/fhrom/bin/wget -O /tmp/an758x-stock2ubi http://192.168.1.10:8000/an758x-stock2ubi
ls -l /tmp/an758x-stock2ubi      # 应为 1014744 字节
chmod +x /tmp/an758x-stock2ubi
```

备选传输（前者失败再用）：
- `busybox wget -O /tmp/an758x-stock2ubi http://192.168.1.10:8000/an758x-stock2ubi`
- PC 上起 TFTP 服务，光猫 `tftp -g -r an758x-stock2ubi 192.168.1.10`
- U 盘（需 root 挂载，不推荐）
- telnet 文本传输（`uuencode`/`uudecode`，1 MB 变 1.4 MB 文本，最笨但零依赖）

**3.2 启动 stock2ubi**

```sh
/tmp/an758x-stock2ubi
# 若报内核版本不符（它要求 5.4.55）：
/tmp/an758x-stock2ubi --ignore-kernel-version
```

- 默认监听 **3333**；要改：`--listen 192.168.1.1:3333`。
- 从**串口 root** 启动最稳（没有 telnet 空闲超时问题）。
- 如果从 telnet 启动：**每 20–30 秒切回 telnet 窗口按一下回车**，否则会话超时、程序退出。

**3.3 在 PC 上备份 17 个分区**

浏览器打开：

```
http://192.168.1.1:3333/
```

页面会读 `/proc/mtd` 列出全部分区，逐个点下载（文件名形如 `mtd13-factory.bin`）。**全部下完**，存到：

```
光猫-CT-HG5585F\备份\原厂-YYYYMMDD\
```

必须齐全的（缺一不可）：

| 分区 | 大小 | 作用 |
|---|---|---|
| `mtd13 factory` | 3,145,728 B | **PON 校准 + WiFi EEPROM + MAC/SN**，缺了 PON/WiFi 起不来 |
| `mtd0 boot` | 2,621,440 B | 原厂引导，回滚用 |
| `mtd1 bootflag` | 524,288 B | 启动槽标志 |
| `mtd2/6 KernelA/B` | 6,291,456 B ×2 | 双系统内核 |
| `mtd5/9 RootfsA/B` | 62,914,560 B ×2 | 双系统根文件系统 |
| `mtd3/4/7/8` | 8,396 / 62,906,164 B ×2 | Rootfs 头/数据（有的页面会单列） |
| `mtd10 apps` | 67,108,864 B | 应用 |
| `mtd11/12 frameworka/b` | 16,777,216 B ×2 | 框架 |
| `mtd14 userlocalct` | 2,097,152 B | 用户本地（CT 名字可能不同） |
| `mtd15 apps` | 50,536,448 B | 应用 |
| `mtd16 userdata` | 10,031,104 B | 用户数据 |

> 实际大小以页面显示为准（不同固件版本可能有差异）。**下完核对字节数**，不要只看文件名。

**3.4 校验备份**

```powershell
cd D:\AI\路由\光猫-CT-HG5585F
Get-ChildItem 备份\原厂-*\*.bin | Select-Object Name,Length | Sort-Object Name | Format-Table -AutoSize
# 生成哈希清单
Get-ChildItem 备份\原厂-*\*.bin | Get-FileHash -Algorithm SHA256 |
  ForEach-Object { "$($_.Hash.ToLower())  $($_.Path)" } |
  Set-Content 校验\备份-sha256.txt
```

**3.5 把 mtd13 转成 ponwrt 要的 1 MiB**

> 关键：`mtd13` 的 3 MiB **不是**裸布局。CU 机实测：在原始 `mtd13` 的 `0x2000/0x2010/0x2020` 处读不到 MAC/SN（全是 `FF`）——身份数据在分区内部的 UBI/UBIFS/容器里。必须用 `fiberhome-factory` 解析并重排成 1 MiB。

1. 双击运行 `物料\工具\fiberhome-factory.exe`（Windows GUI，Rust 程序，无需安装）。
2. 打开/拖入 `备份\原厂-YYYYMMDD\mtd13-factory.bin`。
3. 检查它解析出的五项：
   - **APONCAL**（PON 光模块校准，2 KB）
   - **MT7916 EEPROM**（WiFi，4 KB）
   - **Base MAC**（6 B）
   - **PON serial number**（8 B）
   - **Device serial**（32 B）
4. 另存为 `备份\原厂-YYYYMMDD\factory-1m.bin`，**必须正好 1,048,576 字节**。

**3.6 校验 1 MiB 镜像（本机可验证的硬指标）**

```powershell
$f = "备份\原厂-YYYYMMDD\factory-1m.bin"
"size = $((Get-Item $f).Length)"          # 必须 1048576
# 用 PowerShell 读关键偏移（CU 机已实测的布局）：
function HexAt($p,$off,$len){ $fs=[IO.File]::OpenRead($p); $fs.Position=$off; $b=New-Object byte[] $len; [void]$fs.Read($b,0,$len); $fs.Close(); ($b|%{$_.ToString('x2')}) -join ' ' }
HexAt $f 0x0 16      # 期望以 41 50 4f 4e 43 41 4c ("APONCAL") 开头
HexAt $f 0x1000 2    # 期望 16 79（MT7916 EEPROM magic）
HexAt $f 0x2000 6    # 期望 = 贴纸 MAC
HexAt $f 0x2010 8    # 期望 = PON SN（FHTT + 8 hex）
HexAt $f 0x2020 32   # 期望 = 设备 SN 的 ASCII
```

判定：
- [ ] 大小 = 1,048,576
- [ ] `0x0` 有 `APONCAL` 标记
- [ ] `0x1000` = `16 79`
- [ ] `0x2000` = 贴纸 MAC
- [ ] `0x2010` = PON SN
- [ ] `0x2020` = 设备 SN

任何一项不符 → **停**，回 3.5 检查导入模式（原始/UBI/UBIFS 选错会解析失败），或换一台电脑重试。**不要带着错误的 factory 进入阶段 4。**

**3.7 归档**

- 备份目录整个复制一份到 NAS/移动硬盘（异地副本）。
- 更新 `数据模板/identity-ct.json`、`数据模板/备份清单.md`、`校验/备份-sha256.txt`。
- 在 `数据模板/刷机记录.md` 记一行。

> **决策门 B**：17 分区齐全 + `factory-1m.bin` 五项校验通过 → 才能进阶段 4。否则停。

## 阶段 4 · 写引导（10–20 分钟）

> 目标：把 NAND 开头的 BL2 和 `bl31-u-boot.fip` 换成新 U-Boot，让设备重启后进 `http://192.168.0.1` 的恢复页。

### 路线 1 · 在 stock2ubi 的 `:3333` 页面里写（推荐）

同一页面（`http://192.168.1.1:3333/`）往下滚，有两个上传框：

1. 上传 `物料\引导\an7581-fiberhome-hg5585f-ct-firstblock.bin`（128 KB，整块写 NAND `0x0`；比 `preloader.bin` 少一步擦除，优先用它）。
2. 上传 `物料\引导\an7581-fiberhome-hg5585f-ct-bl31-u-boot.fip`（341 KB）。

工具会自动写入并重启（约 1–3 分钟）。**不要中途断电。**

### 路线 2 · 串口 XMODEM（路线 1 的 fip 上传失败时）

前置：`firstblock` 已经写进 NAND（由 stock2ubi 完成）。若 firstblock 也没写，见 `05` 的高级恢复。

1. 串口线接好，**先**运行脚本（它会等 "Press x"）：
   ```powershell
   pwsh -File .\脚本\xmodem-send-fip.ps1 -Port COM7
   ```
2. 给光猫**断电再上电**。
3. 脚本看到 BL2 的 `Press x` 提示后自动发 `x`，等到 `C`（XMODEM 握手）就开始传 fip。
4. 传输完成后设备会自动启动到 U-Boot（或先报 `System boot failed, starting Web recovery`，属正常——新 U-Boot 还没有 UBI 系统）。

> 该脚本默认发送 **CT 版 fip**；换文件用 `-FipPath`。日志自动写 `日志\xmodem-*.log`。

### 判据

- [ ] 设备重启后，网线插 **LAN2/3/4**，PC 能拿到 `192.168.0.x` 地址
- [ ] `http://192.168.0.1/` 能打开中英文恢复页（首启可能要等约 1 分钟）
- [ ] 串口能看到 U-Boot 菜单/日志（可选）

> **决策门 C**：进不去 `192.168.0.1` 时：
> - 先确认网线**不是插在 2.5G 口（LAN1）**——U-Boot 没有 2.5G PHY 驱动，那个口在恢复页阶段一定是死的。
> - 再试 LAN3/LAN4；PC 设静态 `192.168.0.10/24`。
> - 仍不行 → 串口打断进 U-Boot 控制台（`脚本\uboot-interrupt.ps1`，上电前启动，每 150 ms 发回车抢 3 秒窗口），然后 `bootmenu` 选 Web recovery。详见 `05`。

## 阶段 5 · U-Boot 首次安装（15–30 分钟）

网线插 **LAN2/3/4**，浏览器开 `http://192.168.0.1/`。**按顺序**做五步（顺序错了 WiFi/光模块会起不来）：

1. **重建 UBI / Rebuild UBI** —— 清空并重建 UBI 卷（fip / ubootenv / factory / fit / rootfs_data）。
2. **写入 fip / Write fip** —— 再上传一次 `an7581-fiberhome-hg5585f-ct-bl31-u-boot.fip`（写入 UBI 的 fip 卷，供以后自恢复）。
3. **恢复板级数据 / Restore board data** —— 上传 `factory-1m.bin`（阶段 3 生成的那份）。**这一步决定 PON 和 WiFi 能不能起来。**
4. **上传系统 / Upload system** —— 上传 `物料\固件\ponwrt-airoha-an7581-fiberhome_hg5585f-ct-squashfs-sysupgrade.itb`（约 58 MB，耐心等）。
5. **启动系统 / Boot system**。

预期：约 1–3 分钟后设备重启进入 OpenWrt，LAN 默认 `192.168.31.1`，root 空密码。

> ⚠️ 如果第 3 步上传后报错/容量不符：说明 `factory-1m.bin` 不对，**停下来**，回阶段 3 重新转换。不要跳过直接启动。
> ⚠️ 如果第 4 步后启动失败：U-Boot 的 `boot_ubi` 只在读不到 FIT 时才回退 Web recovery；内核 panic 不会自动回退。此时串口 3 秒窗口打断 → `bootmenu` → Web recovery 重刷（见 `05`）。

## 阶段 6 · 首启 + 配置（20–40 分钟）

**6.1 离线首启，先改 LAN（必做）**

ponwrt 默认 LAN 是 `192.168.31.1`，**和现网主路由完全同段**。首次启动时**不要**把 CT 接到家里交换机，只让 PC 直连。

```sh
# 浏览器 http://192.168.31.1  （root 空密码）
# 或 ssh root@192.168.31.1
uci set network.lan.ipaddr='192.168.88.1'
uci set network.lan.netmask='255.255.255.0'
uci commit network
/etc/init.d/network restart
```

之后 PC 重新获取 `192.168.88.x`，后台地址变 `http://192.168.88.1`。

**6.2 设密码/主机名/时区**

```sh
passwd                                   # 设 root 密码
uci set system.@system[0].hostname='ct-hg5585f'
uci set system.@system[0].timezone='CST-8'
uci commit system
```

**6.3 PON + 板级数据 + PPPoE**

见 `04-首启配置与验收.md` 的 1–3 节。核心：

- PON 线路模式 `epon-10g-1g`
- EPON OAM `operator=ctc`、LOID = **自家线路的 LOID**（CU 档案里是 `000000000000000014509791`，可复用；密码留空）
- `ge_ports=4`
- 板级数据：LuCI → 网络 → PON → 配置 → PON board data → 上传 `factory-1m.bin`
- 只有接光纤时才配 PPPoE（`pon0.995`，账号见 CU 档案 `02105250448/052356`）

**6.4 WiFi 与 2.5G**

见 `04` 的 4–5 节。测试期建议：
- SSID 用 `ct-test`/`ct-test_5G`，不要和家里 `bernard` 混。
- 5G 用 ch149/80，2.4G ch6/20；country **必须 `CN`**。
- 发射功率调低，测完关掉，避免干扰现网。
- `lan1` 是 2.5G：`ethtool lan1` 应显示 `2500Mb/s`（对端也得支持 2.5G；普通千兆 PC 会协商到 1000，属正常）。

> **决策门 D**：`lan1` 链路正常、WiFi 能起、PON 注册（若接光纤）成功 → 进阶段 7。任一项失败先看 `04` 的排查表，别急着重刷。

## 阶段 7 · 验收（20–40 分钟）

逐项打勾（命令见 `04`）：

- [ ] `cat /sys/kernel/debug/airoha-xpon-pon0/line` → `lifecycle: operational`

- [ ] 备份 `sysupgrade -b /tmp/ct-config.tar.gz` 并拉回 PC
