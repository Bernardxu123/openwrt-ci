# 04 · 首启配置与验收

> 适用：CT 机刷完 **ponwrt CT 版**、第一次进系统之后。
> ⚠️ 刷 **QWRT** 的配置/验收看 `08-QWRT刷机流程.md`；本文的 2.5G/热重启/验收思路可参考，但默认网络形态不同（QWRT lan1=WAN、LAN 192.168.1.1）。
> 默认状态：LAN `192.168.31.1`、root 空密码、SSH 22 开、WiFi 关、WAN 预置 `pon0.995` PPPoE。
> 先做第 1 节（改 LAN），再接家里网络。

---

## 1. 第一件事：改 LAN，避免和现网撞段

ponwrt 默认 `br-lan = 192.168.31.1/24`，与现网主路由**完全同段**。首次启动只让 PC 直连，不要接交换机。

```sh
# 浏览器 http://192.168.31.1（root 空密码）或 ssh root@192.168.31.1
uci set network.lan.ipaddr='192.168.88.1'
uci set network.lan.netmask='255.255.255.0'
uci commit network
/etc/init.d/network restart
```

PC 重新拿 `192.168.88.x`，后台变 `http://192.168.88.1`。

顺手做：

```sh
passwd                                    # 设 root 密码
uci set system.@system[0].hostname='ct-hg5585f'
uci set system.@system[0].timezone='CST-8'
uci set system.@system[0].zonename='Asia/Shanghai'
uci commit system
/etc/init.d/system restart
```

```sh
# 确认版本与硬件
cat /etc/openwrt_release
uname -a
cat /proc/cpuinfo | grep -E 'model name|Processor' | head -4
free -m
df -h
```

## 2. PON 配置（不接光纤也能先配好）

### 2.1 LuCI 路径

`网络 → PON → 配置`：

| 项 | 值 | 说明 |
|---|---|---|
| PON line mode | **`epon-10g-1g`** | 10G/1G 非对称；**不要选 `10g-10g`** |
| EPON OAM operator | **`ctc`** | CU 机实测：`ieee` 能 MPON 注册但 `service_ready=0` |
| LOID | 自家线路 LOID（CU 档案：`000000000000000014509791`） | 只在你自己的线路上有意义 |
| LOID password | 留空 | EPON 只认 LOID |
| ge_ports | `4` | 4 个以太口（1×2.5G + 3×GE） |

> 若页面字段名不同，以 `uci show pon` 为准。

### 2.2 等价 UCI

```sh
uci show pon
uci set pon.line0.mode='epon-10g-1g'
uci set pon.line0_oam.operator='ctc'
uci set pon.line0_oam.loid='000000000000000014509791'
uci set pon.line0_oam.ge_ports='4'
uci commit pon
/etc/init.d/pon reload
```

### 2.3 写板级数据（factory 1 MiB）

`网络 → PON → 配置 → PON board data` → 上传 `备份/原厂-YYYYMMDD/factory-1m.bin`（1,048,576 B）。
这一步把 PON 校准 + WiFi EEPROM + MAC/SN 写进 `factory` 卷。**没做这步，PON 和 WiFi 都起不来。**

### 2.4 判据（不接光纤时）

```sh
# 找 debugfs 节点（路径可能随版本变）
find /sys/kernel/debug -maxdepth 2 -iname '*pon*'
cat /sys/kernel/debug/airoha-xpon-pon0/line
cat /sys/kernel/debug/airoha-xpon-pon0/registration

# 进程/驱动
ps | grep -E 'pond|ponctl'
dmesg | grep -Ei 'airoha|pon|bosa' | tail -50
```

不接光纤时正常现象：`line` 显示 `lifecycle: down` 或 `init`、`registration` 无 LLID。**这不算失败**，接光纤后再看。

### 2.5 接光纤后的成功标志

```sh
cat /sys/kernel/debug/airoha-xpon-pon0/line
#   lifecycle: operational
cat /sys/kernel/debug/airoha-xpon-pon0/registration
#   EPON LLID0 registered: LLID=0x....
#   service_ready: 1
```

排查顺序：
1. `ponctl` 模式是否 `epon-10g-1g`；2. OAM 是否 `ctc`；3. LOID 是否与线路一致；4. 板级数据是否写入；5. 收发光（`luci-app-pon-status` 或 `ponctl`）。
6. 若 `service_ready=0` 且 OAM 是 `ieee` → 改 `ctc`。

## 3. PPPoE / WAN

ponwrt 默认已预置 `wan = pon0.995` 的 PPPoE（见 `编译文档.md`）。先看：

```sh
uci show network.wan
# 期望：network.wan.proto='pppoe'、device='pon0.995'
```

填账号（CU 档案里的联通账号，**只在你家线路上用**）：

```sh
uci set network.wan.username='02105250448'
uci set network.wan.password='052356'
uci set network.wan.ipv6='auto'
uci commit network
/etc/init.d/network restart
```

验证：

```sh
ifstatus wan | grep -E 'up|address|proto' | head
ip -4 addr show pppoe-wan
ping -c 3 223.5.5.5
nslookup www.baidu.com
logread -e pppd | tail -20
```

> VLAN：联通家宽上网 VLAN 是 **995**，CU 原厂是在光猫侧解标签后桥接。ponwrt 直接建 `pon0.995` 跑 PPPoE，因此**不需要**在 `wan` 上再加 `.995` 子接口。若你的线路 VLAN 不同，改设备名 `pon0.<VID>`。

## 4. 2.5G 口（`lan1`）验证

CT 的 `lan1` 是外置 **MaxLinear GPY211C**（`gdm4` + `2500base-x`，reset GPIO34）。发布包已含 PR #34 的修复（DTB 里 `ethernet-phy-id67c9.de10`）。

```sh
ip -br link
cat /sys/class/net/lan1/carrier      # 1 = 有链路
cat /sys/class/net/lan1/speed        # 2500（对端支持时）
ethtool lan1 2>/dev/null | grep -E 'Speed|Duplex|Link detected'
dmesg | grep -Ei 'gpy|gdm4|2500' | tail -20
```

- 对端是普通千兆 PC/交换机 → 协商到 `1000Mb/s`，**正常**，不代表失败。
- 想真正跑 2.5G：对端要有 2.5G 网卡/交换机；用 `iperf3` 测。

### 4.1 热重启回归（重点）

PR #34 修的是「热重启时 GPY211C reset 时序竞态导致 `lan1` NO-CARRIER 到下次冷启动」。刷完必须验证：

```sh
# 连续 3 次
reboot
# 起来后（等 60–90 秒）：
cat /sys/class/net/lan1/carrier
cat /sys/class/net/lan1/speed
```

- 3 次都有 carrier → 通过。
- 某次 NO-CARRIER：
  1. 先冷启动（断电 10 秒再上电）确认能恢复；
  2. `dmesg | grep -i gpy` 看 probe/reset 报错；
  3. 记录是「第几次热重启失败」，写进 `数据模板/刷机记录.md`；
  4. 临时对策：冷启动使用；根治需改 DTB/驱动（本包不带源码构建，找上游 issue）。

> 不要用 `ifconfig lan1 up` 之类硬拗；PHY 没 probe 出来时上层操作无效。

## 5. WiFi（MT7916）

ponwrt 默认 WiFi 关闭（小米 AP 继续做覆盖）。测试时再开，且**用独立 SSID、低功率**，避免干扰现网。

```sh
uci show wireless | head -40
# 打开 radio0/radio1（2.4G/5G）
uci set wireless.radio0.disabled='0'
uci set wireless.radio1.disabled='0'
uci set wireless.radio0.country='CN'
uci set wireless.radio1.country='CN'
uci set wireless.radio0.channel='6'
uci set wireless.radio0.htmode='HE20'
uci set wireless.radio1.channel='149'
uci set wireless.radio1.htmode='HE80'
uci commit wireless
wifi reload
```

SSID/密码在 LuCI `网络 → 无线` 里改（或用 `uci set wireless.default_radio0.ssid=...`）。建议 `ct-test` / `ct-test_5G`，WPA2。

验证：

```sh
iw dev
iwinfo
dmesg | grep -Ei 'mt7915|mt7916|eeprom|thermal' | tail -30
```

- 没有 WiFi 接口 / 驱动报 EEPROM 错 → 板级数据没写对（`factory` 0x1000 必须是 `16 79` 开头）。回 `03` 重转重写。
- `mt7915e` 热区注册失败（`-2`）在 CU 机上是无害告警，可忽略。
- 802.11ax/160MHz：CT 与 CU 同 MT7916，160MHz 取决于信道与法规；测试期用 80MHz 更稳。

## 6. 系统与分流

```sh
# 包管理是 apk（不是 opkg）
apk update
apk add iperf3 ethtool tcpdump     # 按需

# 代理：镜像自带 Passwall，默认未启用；节点/订阅自行配置
uci show passwall | head
/etc/init.d/passwall status

# flow offload 现状
uci show firewall | grep flow
nft list flowtable inet fw4 2>/dev/null
```

### 6.1 硬件卸载（可选，先验收再开）

发布包 `v2026.10.18`（commit `5b12fdb`）的默认逻辑是「有分流内核 → `flow_offloading=1` + `flow_offloading_hw=0`」，`packet_steering=1`。

但 **2026-10-20 的实测已经推翻了「hw 卸载会绕开 tproxy」的旧假设**：tproxy 在 prerouting 就把包截下并本地投递，被代理的 flow 根本进不了 forward 方向的 flowtable，PPE 看不到它；硬件卸载只作用于未被代理的直连/转发流量。现网（CU 机 ponwrt）实测：直连下行 ~670 Mbps 时四核 busy 仅 ~4%，`npu_attached=1`，代理出口不变、YouTube 正常。

这套改动在源码 commit `ffd1dd6`，**晚于发布包**，所以刷完要手工设（确认基本功能都过了再做）：

```sh
uci set firewall.@defaults[0].flow_offloading='1'
uci set firewall.@defaults[0].flow_offloading_hw='1'
uci set network.globals.packet_steering='2'   # RPS-only，绕开 packet-steering.uc 对 airoha NAPI 名的误判
uci commit firewall
uci commit network
/etc/init.d/firewall restart
/etc/init.d/network restart

# 验证（路径名以实际为准）
cat /sys/kernel/debug/ppe/entries 2>/dev/null | wc -l
nft list flowtable inet fw4
```

- 若出现「部分站点直连/规则不生效」，先查 tproxy 规则，不要先怀疑 hw offload；仍要回退就：
  ```sh
  uci set firewall.@defaults[0].flow_offloading_hw='0'; uci commit firewall; /etc/init.d/firewall restart
  ```
- 不要在这台 512 MB 机器上同时开 Passwall + OpenClash。
- `packet_steering=2` 的原因：官方 ucode 按 netdev 名匹配 NAPI 线程，airoha 的线程名是 `napi/qdma_eth-0` 而 netdev 叫 `pon0`，匹配失败会把 32 条 RX 队列的 RPS 全塌到 CPU0；设 `2` 可恢复四核 RPS。

## 8. 常见问题

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| `lan1` 一直 NO-CARRIER | 热重启 PHY 竞态 / 对端不支持 2.5G / 网线差 | 换线换口；冷启动；看 `dmesg gpy`；对端千兆会显示 1000 而非 2500 |
| PON `lifecycle: down` | 没接光纤 / 模式错 / 板级数据没写 | 接纤；`epon-10g-1g`；重写 board data |
| `service_ready: 0` | OAM 用了 `ieee` | 改 `ctc` |
| PPPoE 认证失败 | 账号/密码/VLAN 错；LOID 未注册 | 核对 CU 档案；看 `logread -e pppd` |
| 后台打不开 | LAN 改段后 PC 还是旧地址 | 重新 DHCP / 手动 `192.168.88.10` |
| WiFi 不出现 | factory EEPROM 缺失/错 | 重转 `factory-1m.bin` 并重写 board data |
| 系统起不来 | sysupgrade 包不对 / UBI 没重建 | 串口打断进 U-Boot → Web recovery 重刷（`05`） |
| 内存吃紧 | Passwall + 大规则 | 减规则/换轻节点；不要开 OpenClash |
