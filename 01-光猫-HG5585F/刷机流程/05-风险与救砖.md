# 05 · 风险与救砖

> 先记住三句话：
> 1. **U-Boot 恢复页（`192.168.0.1`）是唯一的软着陆通道**，只要它还在，几乎都能救。
> 2. **U-Boot 里 2.5G 口是死的**，别把「2.5G 没反应」当成砖。
> 3. **原厂 CT 固件官方不提供下载**；刷前备份是最后防线，但不是「一键还原」。

---

## 1. 风险矩阵

| 风险 | 概率 | 影响 | 预防 | 出事怎么办 |
|---|---|---|---|---|
| 刷错 `-cu` 包 | 中 | `lan1` 废、WAN 不对 | 只从 `物料/固件` 取包；核对文件名含 `-ct` | U-Boot 重刷 `-ct` 包；不需要救砖 |
| 没备份 `mtd13` | 中 | PON/WiFi 永久起不来 | 阶段 3 强制门禁 | 无法跨机移植；只能找回原备份或放弃 PON/WiFi |
| factory 转换错（1 MiB 不对） | 中 | PON/WiFi 不起 | 五项校验（`03` 7.3） | 重新转换 + U-Boot 重写 board data |
| 写 NAND 时断电 | 低 | BL2/U-Boot 损坏 | 用稳定的电、别在写入时拔线 | 串口 XMODEM / 临时 U-Boot 重写（见 §4） |
| 默认 LAN 撞段 | 高 | 家里网络异常 | 首启离线、先改 `192.168.88.1` | 断开 CT，改回 |
| 热重启 `lan1` NO-CARRIER | 中 | 2.5G 口暂时不可用 | 发布包含 PR #34 修复；仍要实测 | 冷启动；记录；等上游修 |
| 误以为进不了 U-Boot 是砖 | 高 | 白折腾 | 用千兆口、静态 IP、等 1 分钟 | 按 §3 排查 |
| 刷机后想回原厂 | 高 | 回不去 | 刷前问卖家要 CT 原厂包 | 见 §5（现实是：没有包就回不去） |

**不可逆点**：
- 擦除/覆盖 `mtd13 factory` 且没有备份；
- `Rebuild UBI` 覆盖原厂 UBI 卷（原厂系统就没了）；
- 写坏 BL2 且没有串口。

## 2. 砖的分级

| 级别 | 现象 | 还能救吗 | 入口 |
|---|---|---|---|
| **L0 假砖** | 2.5G 口不亮、LAN2 能进 `192.168.0.1` | 能 | 换千兆口即可 |
| **L1 软砖** | 系统起不来，但 `192.168.0.1` 恢复页能开 | 能 | U-Boot Web recovery 重刷 |
| **L2 引导在、系统无** | 开机报 `System boot failed, starting Web recovery` | 能 | 同上；或串口 XMODEM 送 fip |
| **L3 BL2 在、U-Boot 无** | 串口有 BL2 日志、提示按 `x` 等 FIP；无 Web | 大概率能 | 串口 XMODEM 送 fip → 临时 U-Boot → 写 firstblock/fip |
| **L4 BL2 坏/无串口输出** | 上电无任何输出、无 Web、无 DHCP | 难 | 拆机 NAND 编程器 / 换机（本包不覆盖） |

## 3. 进 U-Boot 恢复页的正确姿势

### 3.1 网络侧

1. 网线插 **LAN2 或 LAN3/LAN4**（**绝对不要只插 LAN1/2.5G**）。
2. PC 设自动获取；拿不到就静态 `192.168.0.10/24`，网关 `192.168.0.1`。
3. 浏览器 `http://192.168.0.1/`（**http，不是 https**）。
4. 首次启动等 **60–90 秒**；换浏览器/无痕；关代理。
5. 还不行：换网线、换 LAN 口、换 PC 网卡（有些 2.5G 网卡在 U-Boot 下协商异常，换千兆口/USB 网卡）。

### 3.2 串口侧（可靠）

**方法 A：上电前启动抢窗口**

```powershell
pwsh -File .\脚本\uboot-interrupt.ps1 -Port COM7 -Seconds 60
# 然后立刻给光猫上电
```

脚本每 150 ms 发一次回车，抢 `Hit any key to stop autoboot: 3` 的 3 秒窗口。进去后：

```
bootmenu          # 或 help 看菜单
```

**方法 B：BL2 阶段按 `x` 走 XMODEM**

如果串口看到类似 `Press x to send FIP` / `Press x`：

```powershell
pwsh -File .\脚本\xmodem-send-fip.ps1 -Port COM7
```

脚本会自动发 `x`、等 `C`、发 `物料/引导/…-ct-bl31-u-boot.fip`，完成后进入临时 U-Boot。

**方法 C：Reset 键**

- 上游 README 写「上电约 1 秒后按住 Reset 进 Web recovery」。
- CU 机的 U-Boot 二进制里能找到 `Reset held: entering HTTP recovery`、`Reset button read failed` 等字符串 → 按钮处理是**编译进代码**的，不依赖 env 里的 `check_buttons`；所以「按住 reset 进 recovery」**有可能真的可用**（旧报告据 env 无 `check_buttons` 推断"完全没绑"，已被这条字符串推翻）。
- 但 **U-Boot 阶段读的是哪个 GPIO 未验证**（内核/ponwrt DTB 是 **GPIO35**；QWRT CT 包的 DTB 写的是 GPIO0，与实际不符）；CT 机也未实测。
- 结论：**可以试，但别把它当唯一手段**；串口 3 秒打断才是保底。

### 3.3 判断是不是真砖

- 串口有输出 → 不是 L4。
- 串口停在 `Press x` / BL2 → L3，可按 §4 救。
- 串口能进 U-Boot 命令行 → L1/L2，`bootmenu` 进 Web recovery。
- 串口完全无输出、换线换口无效 → 才考虑 L4。

## 4. L3 救援：临时 U-Boot + 重写引导

> 适用：BL2 还在（串口有日志、要求 FIP），但 NAND 里的 U-Boot 坏了/没写。
> 原理：BL2 通过 XMODEM 把 fip 收进 RAM 并启动一个**临时 U-Boot**；在临时 U-Boot 里再把 firstblock/fip 写回 NAND。

1. 串口接好，运行 `xmodem-send-fip.ps1`，上电，等它把 fip 送完。
2. 进入临时 U-Boot 后，先确认环境：
   ```
   version
   mtd list          # 或 mtdparts / nand info，视 U-Boot 版本
   ```
3. 载入 firstblock（两种方式，任选）：
   - **XMODEM**（U-Boot 自带 `loadx`）：
     ```
     loadx 0x80000000
     ```
     然后在 PC 侧用串口工具发 `物料/引导/an7581-fiberhome-hg5585f-ct-firstblock.bin`（XMODEM）。
   - **TFTP**（PC 起 tftpd，U-Boot 有网口驱动）：
     ```
     setenv ipaddr 192.168.0.10
     setenv serverip 192.168.0.2
     tftp 0x80000000 an7581-fiberhome-hg5585f-ct-firstblock.bin
     ```
4. 写 NAND（**地址/大小以 `mtd list` 为准；下面按 128 KB @ 0x0**）：
   ```
   nand erase 0x0 0x20000
   nand write 0x80000000 0x0 0x20000
   ```
5. 再写 fip（若 U-Boot 卷也在 NAND 固定区；多数情况由 U-Boot recovery 的「Write fip」完成，不必手写）。
6. 断电重启，回 §3 进 Web recovery，走正常首次安装（`01` 阶段 5）。

> ⚠️ 第 4 步的 `nand erase/write` 地址来自 CU 机 MTD 布局（boot 在 0x0）。**CT 若 `mtd list` 显示不同，按实际改**。这是高级操作，**没有把握就先问社区/卖家**，别硬写。

## 5. 回原厂：现实情况

| 你手上有什么 | 能否回原厂 |
|---|---|
| CT 原厂完整固件包（卖家给） | 能，按卖家说明刷回 |
| 只有 17 分区备份 | **不一定**。需要知道原厂 MTD 在 NAND 的绝对偏移，并逐分区 `nand write`；UBI 化之后布局已变，**本包未验证此流程** |
| 什么都没有 | 不能。只能继续用 ponwrt/QWRT |

**建议**：
- 刷前就向卖家确认「有没有 CT 原厂固件/一键刷入包」，有就存一份。
- 不要把「17 分区备份」当成「一键还原包」；它是最后的数据来源，不是刷机包。
- 如果目的只是「玩玩然后出掉」，刷前先想清楚：**原厂界面可能回不去**。

## 6. 绝对不要做的事

1. ❌ 把 `-cu` 的 sysupgrade/fip/firstblock 刷到 CT（或反向）。
2. ❌ 用联通版 `Fh-HG5585F-Ubi-Update-1h-V260921-*.bin` 刷 CT。
3. ❌ 跳过 factory 备份直接 `Rebuild UBI`。
4. ❌ 用别的机器的 `factory-1m.bin`（APONCAL 与光模块绑定，跨机无效）。
5. ❌ 在写 NAND 时断电/拔串口/关浏览器。
6. ❌ 把 CT 接到家里交换机时还用默认 `192.168.31.1`。
7. ❌ 克隆现网 CU 的 PON SN/MAC（设备身份冒用，且 OLT 可能冲突）。
8. ❌ 只看 2.5G 口就判断「刷砖了」。

## 7. 出事时的取证清单

按顺序记录，发群/求助时一次给全：

1. 串口完整日志（`日志/serial-*.log`，从上电第一行开始）。
2. 设备指示灯状态（拍照/描述）。
3. PC 网口灯、`ipconfig`、`arp -a` 是否有 `192.168.0.1`。
4. 浏览器访问 `192.168.0.1` 的报错截图。
5. 你最后一步做了什么（刷了哪个文件、哪一步断电）。
6. `物料` 里固件的 SHA256（`校验/sha256sums-all.txt` 对应行）。
7. 是否已备份 `mtd13`、`factory-1m.bin` 是否五项校验通过。
